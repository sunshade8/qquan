# 연구 간 실험 기억과 로컬 기록

기본 슬롯 전략 연구에 적용한다. 모델 가중치를 재훈련하지 않고, 이전에 측정한 실패·유망 사례를 다음 설계의 근거로 전달한다. 연구와 매매는 기존 예산·검증·실행 한도를 유지한다. 이 기능 자체는 수익성 개선의 증명이 아니다.

## 동작

1. 기존 `strategy_generation_runs`에 각 실험의 규칙, 데이터 해시, 비용, 자본, 학습·개발 성과, 실패 분류, 부모 규칙과 변경 이유를 체크포인트로 저장한다. 완료뿐 아니라 중단·실패한 연구도 보존한다.
2. 다음 연구의 첫 설계 전에 동일 소유자의 최근 최대 100개 저장 연구를 읽는다. 새 연구 시작 이전에 저장된 기록만 사용한다. 동일 종목 집합·공급자·봉 주기·엔진·비용·자본을 요구하며, 이전 개발 기간이 현재 최종 시험 기간과 겹치면 제외한다. 데이터 기간이 다른 결과를 직접 성과 개선으로 비교하지 않는다.
3. 실험 해시가 같은 재실행은 한 번만 세고, 슬롯·계열별로 최대 24개를 골라 입력 크기를 제한한다. 이 목록을 연구 안에 동결해 재개·재설계 때 같은 근거를 읽는다. 전부 실패한 경우도 정상적인 연구 기록이다.
4. 설계 모델은 `memoryUse`에 참조한 실험 ID, 회피/수정/재시험, 이유를 남겨야 한다. 존재하지 않는 기록 인용은 거부한다. 기억에 있는 실패 규칙을 이름만 바꿔 그대로 제안하면 명시적인 `retest` 근거가 있어야 한다. 다른 데이터에서 같은 규칙을 시험하는 것은 유효할 수 있으므로 영구 금지하지 않는다.
5. 새 실험 결과가 다시 저장되고 이후 연구의 근거가 된다. 현재 연구의 최종 평가와 다른 연구의 최종 결과는 설계 입력에서 제외한다. 기존 `passed: false` 독립성 제한은 해제하지 않는다.

실패 원인에 따른 다음 행동은 측정치 해석을 돕는 지침이다. 비용 잠식은 총손익/비용 비교, 무거래는 조건별 차단 수 확인, 수익 집중은 표본 확대, 실행 실패는 데이터/실행 복구를 우선한다. 이를 인과관계가 증명된 결론으로 취급하지 않는다.

## 로컬 파일

연구 CLI는 서버 주소별 소유자 쿠키를 로컬 `session-*.json`에 권한 600으로 보존한다. 매번 실행할 때 새 소유자가 되어 이전 연구를 읽지 못하던 문제를 방지한다. `RESEARCH_COOKIE`를 주면 해당 쿠키를 우선한다. 이 세션 파일도 Git 제외 대상이다.

경로: 프로젝트의 `research-logs/strategy/<연구 ID>/` (Git 제외).

- `run.json`: 현재 연구 기록, 참조 기억, 설계 및 최종 평가.
- `experiments.jsonl`: 실험당 한 줄. 실행 규칙·조건·성과·실패·변경 이유·출처를 포함한다.
- `snapshots/<내용 해시>.json`: 변경 이력을 중복 없이 보존한다.
- `README.md`: 사람이 읽는 실패 분류별 요약.

DB가 앱과 설계 에이전트의 기준 저장소이고 로컬 파일은 검토/백업용 복제다. Cloudflare/Vercel의 실행 파일시스템에 영구 파일을 쓰지 않는다. 브라우저만 실행해도 DB 기록과 연구 간 참조는 작동하지만, 로컬 파일 갱신에는 로컬 러너 또는 아래 동기화 명령이 필요하다. 파일을 수정한다고 에이전트의 근거가 바뀌지는 않는다.

```sh
# 실제 거래를 시작하지 않고 기존 연구를 진행하며 매분 기록을 복제
npm run trader -- --generation-only

# 로컬 앱의 모든 기존 슬롯 연구를 한 번에 저장 (페이지네이션)
npm run research:logs -- --runner --url http://localhost:3000

# 이미 저장된 과거 run.json을 오프라인으로 보관
npm run research:logs -- --import outputs/slot-research/agent-validation/run.json
```

`scripts/research/run-slot-research.mjs`도 매 단계 뒤 자동 기록한다. 해당 스크립트는 새 유료 연구를 시작할 수 있다. 위 동기화/오프라인 import는 모델·주문을 호출하지 않는다. `--import`는 검증되지 않은 파일을 DB나 설계 근거에 삽입하지 않는다. 원본 DB의 기록이 있으면 다음 연구가 이를 자동 참조한다. 기존 수동 생성·급등주 연구에는 이번 기억 선택기를 연결하지 않는다.

원격 전체 기록 복제는 서버와 러너의 기존 `STRATEGY_RUNNER_SECRET` 인증이 필요하다. 일반 API 호출은 소유자 쿠키의 기록만 반환한다. 저장된 API 호출 원문·소유자 ID·환경변수는 파일에 내보내지 않는다. 사용자가 연구 설명에 쓴 내용과 실행 규칙은 기록되므로 로컬 파일을 공개 저장소에 올리지 않는다.

`snapshots`가 변경 이력의 기준이다. 여러 러너가 동시에 복제하면 `run.json`은 마지막 작성자의 스냅샷이 될 수 있지만 모든 내용 해시 스냅샷이 남으며 다음 동기화가 현재 상태를 복원한다. 오래된 기록 삭제/보존 기한은 자동 적용하지 않는다.
