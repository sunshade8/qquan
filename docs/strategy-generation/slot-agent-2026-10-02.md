# 프로그램 내 슬롯 연구 에이전트 연결 및 실측 (2026-10-02 KST)

연구 시작 버튼과 `action=research`의 기본 경로를 설계 에이전트에 연결했다. 이 문서의 실측은 앱의 연구 실행기가 저장한 결과다. 별도 스크립트는 목록 조사·산출물 내보내기·동일 규칙 재계산에만 사용했다. 실주문은 실행하지 않았다.

## 실행 경로와 변경

`createSlotResearch` → 데이터·기간·슬롯·목표·비용 동결 → **design**(사용자 입력과 학습 통계로 네 계열 일괄 설계) → **search**(기존 엔진에서 슬롯별 최소 8개 규칙·진단 수정안 비교) → **reflect**(학습·개발 진단으로 후속 설계 배치) → 추가 로컬 실험 → 후보·결합 규칙 동결 → 유망 후보만 독립 위험 검토·공통 최종 시험·독립 결과 검토.

- `lib/slot-research-agent.ts`: 실제 모델 호출용 구조화 스키마, 제한된 설계 입력, 원본 주기·계열·진입 시각 검사, 배치 버전과 입력/출력 해시. 서술은 실행 코드로 평가하지 않고 기존 규칙 언어로 컴파일한다.
- `lib/slot-research-store.ts`, `lib/strategy-generation.ts`: 기본 `designMode=agent`, 단계별 체크포인트, 기존 비용 예약·재개·lease 연동. 초기 설계와 재설계는 한 번에 네 씨앗 규칙을 만들고, 많은 변형은 로컬에서 비교한다. 기존 `local` 모드는 사용자가 선택할 수 있다.
- 설계 입력은 명시적으로 허용한 필드만 구성한다. 최종 결과·최종 가격·계좌 결합 결과를 전달하지 않는다. 초기 입력은 학습 통계, 후속 입력은 학습·개발 실측 진단만 포함한다. 전 구간 원시 분봉을 모델에 보내지 않는다.
- 변형은 실제 부모 규칙을 계승한다. 신호 부족 시 `gte` 하한을 낮추고 `lte` 상한을 높이도록 방향 검사를 추가했다. 이 추가 회귀 수정은 향후 생성에 적용하며, 실측 실행에서 동결한 98개 규칙과 원장은 변경하지 않았다. 새 이름을 붙인 동일 실행 규칙은 같은 데이터·비용·자본·엔진·검증 경계의 해시 결과를 재사용하며, 시도 이력의 이름·부모·목표 판정은 현재 연구에 맞게 유지한다.
- 신규 다운로드 실패는 정상 과거 캐시를 버리는 이유가 되지 않는다. 원본 출처 및 봉 품질 검사를 유지하고, 보충 실패와 누락을 표시한다. 데이터뿐인 실패는 실측 완료가 되지 않는다. 전체 실행 종료와 슬롯별 측정 상태도 별도로 저장한다.
- 화면에 에이전트의 배치별 설계·관측 실패·실제 변경, 슬롯 표, 일별 자본곡선, 거래 원장, 목표 차이, 원본 주기와 제외 세션을 표시한다. 최종 산출물이 있으면 최종 원장도 내려받을 수 있다.
- 화면 확인 중 발견한 상단 시장 시각의 SSR/브라우저 불일치를 수정했다. 최초 서버·브라우저 렌더를 같게 하고 마운트 후 시각을 표시한다.

## 한도와 기본값

기존 자본 $1,000과 슬롯·목표 환산을 재사용한다. 목표 미선택은 기존 12개 시나리오를 모두 비교하며, 가장 쉬운 것을 대표 목표로 택하지 않는다. 목표 비교의 분모는 **정상 세션 시작 자본 대비 비용 후 일수익률의 평균**이며 정상 무거래 0%를 포함한다. 누락은 분모에서 제외하고 별도 공개한다. 거래 발생일 평균, 누적 복리, 계좌 결합 수익은 별도다.

- 최소 8 / 최대 16후보·슬롯: 네 계열의 기준/진단 수정에 최소 기회를 주고, 추가 배치를 포함한 계열당 네 변형으로 탐색을 제한한다.
- `maxDesignBatches=2`(1–2 설정 가능): 최초 설계와 실측 반영 설계를 배치로 실행한다. 모델 응답 한 번마다 한 후보씩 비싼 검토를 반복하지 않는다.
- 최대 400백테스트·로컬 계산 600초, 최소 범위 이후 최근 8회가 0.005%p 초과 개선을 보이지 않으면 정체로 본다. 개선이 없는 계열의 추가 배분을 줄인다.
- LLM 전체 $8/16/24, 마지막 검토용 35% 예약. 1분봉 연구에서는 최종 슬롯별 3회와 결합 1회 계산도 미리 남긴다. 예산을 다 쓰는 것은 목표가 아니다.
- 기존 표본·낙폭·손실·비용·체결·독립 검토 기준을 유지한다. 다중 시도 수와 반복 선택 사실을 기록한다. 목표 도달과 검증 통과는 별도다.

`config`에서 최소/최대 후보, 백테스트·계산 시간 상한, 정체 길이와 개선 기준을 설정한다. 출처 또는 실행이 막힌 슬롯은 성과 미달로 바꾸지 않는다. 부족한 독립성 증빙을 만들어 통과시키지 않는다.

## 검증·재현 및 제한

- 프로덕션 빌드·전체 314개 회귀 테스트, TypeScript, 변경 파일 ESLint와 diff 검사를 수행했다. 최종 검사 기록은 `outputs/slot-research/agent-validation/validation.json`에 있다.
- 고정 데이터·규칙으로 결과 캐시를 쓰지 않고 **196회 재계산**하여 98개 후보의 요약·진단·일별 잔고·거래 원장이 저장 JSON과 정확히 일치했다. JSON이 -0을 0으로 저장하는 표현만 정규화하며 수치 허용 오차를 적용하지 않는다.
- 데스크톱과 390px 화면에서 9개 슬롯 표, 상세 원장·자본곡선, 페이지 가로 넘침 0, 앱 오류 오버레이 없음을 확인했다. 화면 및 재현 JSON은 `outputs/slot-research/agent-validation/`에 보존했다.
- 합성 가격·모의 LLM을 쓰는 회귀 테스트는 소프트웨어 검증용이다. 위 실측은 실제 저장 시장 자료와 실제 모델 응답이다.

```sh
node --experimental-strip-types scripts/research/audit-slot-data.mjs outputs/slot-research/agent-validation
node --experimental-strip-types scripts/research/verify-slot-replay.mjs outputs/slot-research/agent-validation/run.json outputs/slot-research/agent-validation/reproducibility.json
```

새 연구는 화면에서 시작하거나 `node scripts/research/run-slot-research.mjs`로 같은 **프로그램 연구 API**를 구동한다. `--local`은 내장 규칙 비교다. `--replay 기록.json`은 같은 범위로 새로운 설계 연구를 시작하므로 LLM의 규칙은 달라질 수 있다. 동일 규칙 재현은 위 `verify-slot-replay.mjs`를 사용한다.

남은 제한: 연속 일반 세션 1분봉, 당시 호가·체결 증거, 과거 노출의 독립성 증빙이 없어 실행/독립 최종 통과를 주장하지 않는다. 달력은 보유 일봉·분봉 관측일의 합집합이며 완전한 거래소 달력 인증이 아니다. 현재 유니버스와 수정주가의 한계도 유지한다. 탐색 언어는 현금·정수 주식·매수 후 매도·슬롯당 하루 한 번·완성 OHLCV 조건이며, 사용자 문장을 임의 코드로 실행하거나 주문하지 않는다.
