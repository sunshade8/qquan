5. 학습의 거래 수·순수익·낙폭 기준을 충족한 후보를 동결하고 SHA-256을 저장한다. 초기 학습은 60%, 남은 기간은 데이터 양에 따라 최대 3개의 시간순 검증/최종검증 쌍으로 미리 구분한다. 각 쌍의 검증·최종검증은 최소 20세션이다.

## 실행 범위와 방어 조건

현재 생성 언어는 현금·정수 주식·매수 후 매도·슬롯당 하루 1회·같은 날 청산이다. 사용자 지정 종목코드와 6개 OHLCV 특징(수익률, VWAP 거리, 레인지 위치, 상대 거래량, 돌파, 레인지 폭)을 AND로 조합한다. 뉴스·실적·옵션·공매도·레버리지·환전·임의 프로그램 전략은 지원하지 않는다.

- 미완성/미래/중복/오래된/누락 봉, 0 거래량, 비정상 가격을 거부한다.
- 매수 가능 USD, 수수료, 1% 현금 여유, 정수 수량, 신호 봉 거래량의 1% 참여 상한을 적용한다. 1주도 못 사면 진입하지 않는다.
- 생성 규칙은 주문 전 실제 브로커 달력으로 세션·휴장·조기 폐장을 확인한다. 슬롯 전체를 지원하지 않는 단축 세션은 쉬어간다.
- 시세·호가 시각이 60초를 넘거나 확인되지 않을 때, 역전 호가, 스프레드 초과, 신호 대비 가격 이탈, 지연된 신호를 차단한다.
- 실전은 미체결 주문과 해당 종목의 기존 계좌 보유를 확인한다. 수동 보유를 전략 소유로 취급하지 않는다. 결제/거래 제한은 브로커 주문 가능 금액·매도 가능 수량·응답을 따른다.
- 일 손실 3% 이후 신규 진입을 멈춘다. 부분체결·취소·거절·슬롯 전환·정지 청산은 기존 주문 상태 머신을 사용한다.
- 주문 전송 전에 주문 의도와 동일 주문 식별자를 DB에 저장한다. 저장 실패 시 전송하지 않는다. 조회 실패 시 잔고나 매도 수량을 추정하지 않는다.
- 응답이 유실된 주문은 중복 방지 시간 이후 재전송하지 않는다. 거절로 추정하지 않고 미확정 상태를 유지해 후속 주문과 정지 완료를 막으며, 토스 내역 확인·계좌 대사가 필요하다고 표시한다.
- 실행 시작 당시의 전략 목록을 고정한다. 이후 생성한 전략은 다음 실행부터 적용한다.

분봉은 호가 대기열·체결 가능 수량·거래중단 사유·특수 기업행동을 완전히 재현하지 못한다. 비용·매도세 가정은 `broker-costs.ts`를 따른다. 소프트웨어 손절은 러너/시세/브로커 가용성에 의존하며, 중단·갭·장 마감 중 체결을 보장하지 않는다. 규칙 등록은 증권사 기능이나 이 제한을 확장하지 않는다.

## 저장과 실행

`strategy_generation_runs`: 단계/산출물/비용/lease/동결 해시. 한 계좌에서 생성 작업 1개만 동시에 실행.
`strategy_generation_data`: 다운로드한 월별 데이터 스냅샷.
`generated_relay_strategies`: 슬롯 UNIQUE인 승인 규칙과 증거.

단계마다 저장하므로 페이지를 다시 열면 이어진다. 실행 도중 프로세스가 사라져 lease가 만료되면, 결제된 모델 요청이나 미사용 기간을 무심코 재실행하지 않고 실패로 종료한다. 사용자가 새 생성을 시작할 수 있다. 취소한 작업의 늦은 모델 응답은 슬롯을 등록하지 못한다.

`npm run trader`는 매매 틱과 별도의 생성 루프를 돌려 긴 모델 응답이 주문 감시를 늦추지 않게 한다. 페이지와 러너가 모두 꺼져 있으면 작업/주문 감시가 진행되지 않는다. 원격 생성 러너에는 서버와 러너 양쪽의 `STRATEGY_RUNNER_SECRET`이 필요하다. 이 앱의 승인 전략 레지스트리는 기존 live/paper singleton과 같은 **단일 계좌** 범위이며 다중 고객 서비스가 아니다.
