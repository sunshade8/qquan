# CT — Chart Trading

투자 메뉴는 전략 → CT → 급등주 순서다. CT의 주식/코인 선택과 투자 메뉴 선택은 기기에 기억된다. 주식은 기존 Toss 미국 현금 주식, 코인은 Upbit KRW 현물이다. 기본값으로 전략 생성을 시작할 수 있다. 연구 방향, 종목(주식 1–4개, 코인 BTC/ETH/SOL 1–3개), 연구 기간(90–1,095일, 기본 365일), 자본, 연구 비용은 선택 설정이다. 봉 주기는 선택할 수 없다: 새 연구는 항상 **1분봉**으로 설계·백테스트한다(2026-10-13). 이전에 등록된 5/15/60분 패키지는 그대로 유효하다.

## 현재 로컬 데이터 정책 (2026-10-13)

기본 연구는 주식 **NVDA / Massive raw 1m**, 코인 **Binance Spot BTCUSDT / USDT 1m**다.
Settings에서 공유 Parquet 데이터를 먼저 다운로드한다. CT는 로컬 coverage를 사전 검사하고
불변 파일 snapshot/version을 고정하며, 연구 중 과거 시세 API를 호출하지 않는다.
NYSE 캘린더는 2020–2035로 확장했다. NVDA 원주가 분할 경계는 세션 격리로 처리한다.
Binance USDT 연구의 Upbit KRW 실행은 차단한다. 기존 Upbit 기록·포지션 청산은 보존한다.
아래의 기존 실행 검증/저장 기록 중 Upbit, 연구별 수집, 2025–2028 캘린더 설명은 과거 버전 기록이다.
현재 실행 명령과 정책은 [로컬 실행 문서](local-runtime.md)를 따른다.

## 판 정상화 (2026-10-14, 엔진 `ct-pattern-2`)

`docs/prompts/ct-stage1-playing-field.md`의 작업 결과다. 연구 모델을 바꾸기 전에 **판 자체**(비용, 보유 규칙, 관찰 창, 데이터 범위)를 실측 근거로 고쳤다. 새 계약은 `ct-pattern-2`이고 이전 계약·등록 패키지(`ct-pattern-1`)는 저장된 비용·규칙 그대로 같은 결과를 낸다(골든 회귀 테스트 `tests/ct-pattern-1-regression.test.mjs`가 시그널·거래·일별 곡선·게이트를 비트 단위로 고정).

### 천장 측정: 이 판에 비용 후 우위가 있을 수 있는가

[CT 천장 측정 보고서](research/ct-ceiling-2026-10-14.md) (`npm run research:ceiling`, 모델 비용 0). 1분봉 매 시점에서 다음 봉 시가 진입 → 보유 상한(60/240/390봉/당일 청산, 당일 경계 비월경) 안에서 +3×왕복비용에 −1×왕복비용보다 먼저 닿으면 양성으로 라벨링하고, 현재 DSL 10개 피처를 1분(30봉)·1시간(24봉)·일봉(10봉) 규모와 시간대로 모은 31개 피처에 깊이 ≤ 3 트리(잎 최소 표본 = 학습 일수 이상)를 확장 창 **워크포워드 4폴드**로 검증한다. 비용(현재 계약/실측 프로필/각각 2배) × 보유 상한 × 데이터(코인 180일·1년·3년, NVDA 180일·전체) 64개 조합 전부에서 **비용 2배 워크포워드 일평균이 양수인 잎은 없었다**. 64개 중 학습 구간에서 트리가 거래를 고른 조합은 51개이고 그 51개 모두 검증 구간 일평균이 음수다(1배 비용 기준; 가장 덜 나쁜 조합도 거래 4건에 일평균 −0.0004%). 무조건 진입의 거래당 비용 후 평균은 −0.19~−0.67%이고, 학습 구간(표본 내)에서는 64개 중 52개 조합에서 비용 후 양수인 잎이 보였지만(최대 거래당 +1.24%) 표본 밖에서는 어느 폴드 묶음도 양수가 아니었다(양수 폴드 최대 1/4, 해당 조합도 합계 음수). 표본 내에서만 보이는 우위는 판의 우위가 아니라 과적합이라는 뜻이고, 그래서 이 판에서 "학습 구간에서 양수"는 증거가 되지 못한다. 반복 검정은 조합 64 × 폴드 4 × 피처 31 = 7,936건(트리가 평가한 후보 분할 약 170만 개)이다. 이 결과는 2·3번 작업(규칙 언어 확장, 에이전트 구조)을 하지 말라는 근거가 아니라 **무엇을 기대하면 안 되는지**의 기준이다: 단순 피처 세트의 얕은 트리가 못 찾는다는 뜻이지 어떤 규칙도 없다는 증명이 아니다.

### 비용 프로필 (`lib/ct-costs.ts`)

거래소별 **버전이 있는 프로필**이 `replayCT`가 쓰는 수수료·세금·스프레드·슬리피지를 정한다. 새 계약은 프로필에서 숫자를 뽑아 `contract.costs`에 동결하고 `contract.costProfile: {id, version}`을 함께 저장한다. 이전 계약과 등록 패키지는 `costProfile`이 없고 저장된 `costs`만 읽는다(테스트: `tests/ct-contract.test.mjs`). 화면은 연구 시작 카드와 진행 바에 프로필·버전·잠정 여부·왕복 비용을 보여 준다.

| 프로필 | 수수료 | 스프레드·슬리피지 | 출처 |
| --- | --- | --- | --- |
| `binance-spot-usdt` v1 (새 코인 연구) | 편도 0.1%(Regular User maker/taker 0.100%, BNB 할인은 가정하지 않음) | **실측 p90**, 종목·주문 규모별(`lib/ct-cost-measurements.ts`) | [Binance 수수료표](https://www.binance.com/en/fee/schedule), 2026-10-14 확인 |
| `upbit-krw` v2 (참고, 새 계약에 쓰지 않음) | **0.05%**(원화마켓 일반 주문, 매수·매도 동일) — [Open API 주문 가능 정보 문서](https://docs.upbit.com/kr/reference/available-order-information)(수정 2026-10-07)의 `bid_fee`·`ask_fee`·`maker_*` 값 0.0005, 2026-10-14 확인. v1의 0.139%는 **예약주문** 요율로 Open API 일반 주문에 적용되지 않는다. 실전 진입은 주문 가능 정보의 실제 수수료가 0.05%를 넘으면 계속 차단한다 | 실측 p90 | [Upbit Open API](https://docs.upbit.com/kr/reference/available-order-information) |
| `toss-us-equity` v1 (주식) | 기존 `lib/broker-costs.ts`(편도 0.1% + SEC 매도 0.0008%) | 기존 가정 0.05%/0.03%, **측정하지 않음** | `docs/toss-api.md` |

**스프레드·슬리피지 측정** (`scripts/data/measure-orderbook.mjs`, 인증 없는 공개 API만): Binance `depth`(500호가)와 Upbit `orderbook`을 1분마다 BTC·ETH·SOL 스냅샷으로 저장(SQLite `ct_orderbook_samples`)하고, $1,000와 $10,000(자본의 10배) 시장가 매수·매도가 mid를 얼마나 미는지 호가를 직접 걸어 계산한다(Upbit은 KRW-USDT 환산). 프로필 값은 **측정 p90을 올림**한 값이고 측정값 아래로 내려가지 않는다(`--check`가 이를 확인하고 낮으면 실패). 스프레드 = p90 스프레드, 슬리피지 = p90 편도 충격이 반 스프레드를 넘는 부분이라 `spread/2 + slippage ≥ p90 충격`이다. 자본이 1,000 이하면 $1,000 값, 그 이상이면 $10,000 값을 쓰고 선택한 종목 중 최악의 값으로 계약을 만든다.

실측 결과(초기 약 30분 표본): Binance BTCUSDT는 스프레드·충격이 ≈0.00001%로 **가격 틱(0.01 USDT) 수준**이고 ETHUSDT 0.0004%, SOLUSDT 0.009%다. 이전 계약이 가정한 스프레드 0.05% + 슬리피지 0.03%(편도 0.055%)는 BTCUSDT에서 약 4,000–9,000배 과대였다. 그래서 BTC 왕복 비용은 0.3095%에서 **약 0.200%**(수수료 0.1%×2가 거의 전부)로 내려갔다. 반대로 Upbit KRW-BTC는 $1,000에서도 편도 충격 p90 0.06%로 Binance보다 훨씬 비싸다 — Binance 연구와 Upbit 실행이 다르다는 기존 차단 정책의 근거가 하나 더 생겼다.

**잠정**: 측정 72시간(`CT_PROFILE_MIN_HOURS`)을 채우기 전의 프로필은 `provisional`로 표시된다. 샘플러는 72시간 실행으로 시작했다(`npm run data:orderbook -- --hours=72`, 로그 `~/.qquan/logs/orderbook-sampler.log`). 끝난 뒤 `npm run data:orderbook -- --profile --write-lib`로 표를 갱신하고 `--check`로 확인하면 잠정 표시가 사라진다(프로필 버전 변경 시에는 `version`을 올린다). **측정으로 알 수 없는 것**: 신호 봉 종가와 실제 체결 사이의 지연, 큐 위치, 역선택. 프로필은 실거래 비용의 하한이지 예측이 아니며, 게이트의 **비용 2배 스트레스는 그대로 유지**된다.

### 단타 보유 규칙

CT는 단타다: 포지션은 하루를 넘기지 않는다. **코인의 하루는 UTC 00:00 = KST 09:00**이다(게이트의 코인 일별 집계가 이미 UTC 날짜라 하루 손익이 그날 안에서 닫히고, Binance·Upbit의 일봉 경계도 이 시각이다). 주식은 정규장 종료다.

- 청산 방식: 주식 `session`과 같다. 하루의 마지막 거래 봉(UTC 23:59에 닫히는 봉, 주식은 종료 1분 전에 닫히는 봉)의 **종가**로 청산하고 사유는 코인 `day_end`, 주식 `session`이다. 신규 진입은 그 마지막 봉에서 막힌다. 백테스트(`replayCT`), 모의·실전(`ct-trading-engine.ts`), 설계 도구(`query_conditional_returns` 손절·목표 격자, `cost_hurdle`)가 **같은 함수**(`ctDayClosing`, `ctForcedExit`, `ctEntryBlocked`)를 쓴다. `ct-pattern-1` 코인은 이전처럼 연속(강제 청산 없음)이다.
- `maxHoldBars` 상한: 코인 1,440(주식 390 유지). `spec.exit.maxHoldBars`는 시장별로 검증한다.
- `entry.noEntryBeforeDayEndMinutes`(0–240, 기본 0 = 없음): 하루 끝 N분 전부터 신규 진입을 막는다(주식 포함). 0과 생략은 같은 실행 해시다.
- `cost_hurdle`: 코인 보유 지평에 720·1,440봉과 **당일 경계까지**(`bars: 0`, 가변 길이)를 추가했고, 모든 지평을 당일 경계에서 잘라 계산한다(`ct-pattern-2` 계약만; 이전 계약은 이전 표).
- 학습/개발 경계가 UTC 자정에 정렬돼 있으므로 `ct-pattern-2` 코인 연구에서는 포지션이 구간 경계를 넘지 않는다.

### 관찰 창: 상위 시간대

`condition.timeframe`에 **60·240·1440**(1시간·4시간·일봉)을 추가했다(`ct-pattern-2`). 1분 원봉에서 **완성된 봉만** 집계한다(`lib/ct-timeframes.ts`): 코인은 UTC 격자(일봉 = UTC 하루), 주식은 정규장 개장 기준 격자(첫 봉 09:30–10:30…, 조기 폐장·마지막 봉은 짧게, 일봉 = 정규장 한 세션) — 기존 UTC 격자의 "개장 첫 30분은 60분 봉이 되지 않는" 한계를 이 시간대에서는 고쳤다. 1분 중 하나라도 빠진 봉은 만들지 않는다(합성 없음). lookback 상한은 시간 배수와 함께 검증한다: **관찰 가능한 과거는 최대 30일**(`lookback+offset+1`개 봉이 차지하는 일수, 주식은 세션 수; 일봉은 `lookback+offset+1 ≤ 30`).

- 주식: 1·3·12분 조건은 기존대로 세션 안 연속 봉만 쓰고, 60/240/1440 조건은 **이전 세션의 완성 봉**까지 이어 쓴다(주말·휴장은 이어지고, 거래일인데 데이터가 비었으면 끊긴다). **분할·기업행사 경계는 격리**한다(`CT_STOCK_SPLITS`, 예: NVDA 2024-06-10 전후의 창은 합치지 않음).
- 성능: 심볼·시간 배수별 상위봉을 리플레이마다 한 번 만들고(`ctHigherSets`) 이진 탐색으로 참조한다. 구간 밖(`fromMs` 이전, `toMs` 이후) 봉은 시리즈에 넣지 않는다. 코인 1분 원봉을 1,500봉만 들고 다니는 한계는 상위 시간대 조건에 적용되지 않는다(상위 시리즈가 대신한다).
- 실전·모의에서 이 조건을 쓰려면 이력이 필요하므로 `ctRecentBars`의 주식 웜업 일수가 규칙의 조건에서 계산된다(`ctWarmupDays`). Binance 연구 규칙은 Upbit에서 실행하지 않는다(기존 차단).

### 데이터 범위

- 요청 `days`: 90–1,095일(코인 3년). 주식은 로컬 데이터가 있는 만큼(현재 약 2년, Massive 계정은 2024-10-12 이전 구간이 HTTP 403)이며 부족하면 시작 전에 부족 구간을 알려 준다. **기본값은 365일**이다. 근거: 하루 0.4건 수준의 셋업이면 180일의 개발 구간(36일)은 약 14건으로 최소 20건 게이트에 구조적으로 걸리지만 365일(개발 73일)은 약 29건이라 표본이 생긴다. 천장 측정에서는 1년과 3년이 부호를 바꾸지 않았고(둘 다 비용 후 우위 없음) 3년은 리플레이·도구 시간이 3배라 기본으로 쓰지 않는다. 3년은 선택으로 열어 둔다.
- 시간순 60/20/20 분할과 최종 구간 1회 사용은 그대로다. 개발·최종 결과 요약에 **분기별 일평균 순수익과 양수 분기 비율**(`ctStability`)을 추가했다 — 게이트는 바꾸지 않았고 설계자·독립 검토자에게 보여 주는 안정성 정보다.
- 계산 예산: 새 계약 `maxComputeMs` 600초 → **1,200초**. 측정: 1년 BTC 1분봉 `replayCT` 약 1.2초, 3년 약 3.9–4.8초, `query_conditional_returns` 1년 2.1–2.8초·3년 6.3–8.8초, `cost_hurdle` 3년 5.1초(변경 전과 동일 코드 경로는 처리 시간이 같다 — 아래 검증 절). 3년 연구에서 설계 세션당 도구 24회와 실험 묶음을 합치면 600초에 근접하므로 새 계약만 올렸다. 활성 작업 한도 3,600초는 그대로다(이전 계약은 각자 저장된 값).
- **코인 종목 추가**: ETHUSDT·SOLUSDT를 같은 Binance Public Data 파이프라인으로 받는다(`store.py`의 `eth`·`sol` 데이터셋, Settings 버튼·catalog·coverage·품질 보고 동일, 다운로드 스크립트 `scripts/data/download-eth-minute.py`·`download-sol-minute.py`). 연구는 BTC/ETH/SOL 1–3개를 고를 수 있고 종목마다 불변 snapshot이 따로 계약에 고정된다(`contract.dataSnapshots`). 종목 집중도 게이트(80%)는 그대로다.
- **최종 구간 재사용 금지**(`ct_exposure`)는 그대로이고, 이제 **시작할 때** 확인한다: 새 연구의 최종 구간이 같은 시장·종목의 이미 열린 최종 구간과 겹치면 생성이 거부되고 사유(어느 연구의 어느 기간과 겹치는지)가 화면에 표시된다. 데이터 범위가 길어져 이전 최종 구간과 겹치는 경우도 같다.

### 진입 시간 창

`entry.entryWindows`(최대 3개, `{fromMinute, toMinute}`)는 **하루 시작 후 경과 분**으로 쓴다: 코인은 UTC 00:00(KST 09:00), 주식은 정규장 개장(0–389). 신호 판정 시각(마지막 단계 완성 봉의 끝)의 경과 분이 `fromMinute ≤ m ≤ toMinute`일 때만 진입한다(양끝 포함; `{0, 30}` = 개장 후 30분 = 봉 마감 1…30분). 창은 개장 기준이라 조기 폐장일은 하루가 더 일찍 끝날 뿐이다. `noEntryBeforeDayEndMinutes`와 함께 동작한다. 라이브 러너는 `signal.decidedAt`(백테스트와 같은 시각)로 판단한다.

### 레벨·ATR 피처

모두 그 시점까지 완성된 봉만 쓴다. 하루는 코인 UTC 일자, 주식 정규장 세션이다. 하루의 첫 봉이 하루 시작에 정확히 시작하고 그 뒤 봉이 빠짐없이 이어질 때만 값이 있다(분 하나가 빠진 날의 VWAP은 VWAP이 아니다) — 아니면 null. 전일 값은 직전 **완성** 일봉(`prevDailyBar`)에서 오고, 직전 세션이 비었거나 분할 경계를 넘으면 null이다(주말·휴장은 이어진다).

| feature | 정의 | 고정 파라미터 |
| --- | --- | --- |
| `vwap_distance_pct` | 종가 / 당일 누적 VWAP − 1 (VWAP = Σ(전형가×거래량)/Σ거래량, 전형가 = (고+저+종)/3) | lookback 2 · offset 0 · timeframe 1 |
| `prev_day_high/low/close_distance_pct` | 종가 / 전일 고가·저가·종가 − 1 (개장 직후 종가 대비는 갭) | 같음 |
| `day_open_distance_pct` | 종가 / 당일 시가 − 1 | 같음 |
| `opening_range_position` | (종가 − OR 저가)/(OR 고가 − OR 저가), OR = 당일 첫 `lookback`분. 0–1 밖 = 돌파. OR 미완성·고저 같음 → null | `lookback` = OR 길이(≥5분), offset 0, timeframe 1 |
| `day_range_position` | 당일(그 봉까지) 고저 안 위치 0–1 | 고정 |
| `atr_pct` | `lookback`봉 평균 진폭(TR 평균) / 종가 × 100, `timeframe` 완성봉 | |
| `atr_percentile` | 현재 ATR이 최근 `lookback`개 ATR 중 몇 분위(앞선 값 중 현재 이하 비율, 0–1), ATR 길이 `atrLookback`(기본 14) | |

의미 없는 파라미터는 스키마가 고정값을 강제한다(설계자가 쓸모없는 숫자를 탐색하지 못하게). 차트 근거(`signal.references`)는 실제로 쓴 선(VWAP, 전일 고가·저가·종가, 당일 시가, 당일 고저, 시가 범위 상·하단)을 표시한다.

**`unit: "atr"`**: 수익률·거리 조건(`return_pct`, `*_distance_pct`, `range_pct`)의 값을 고정 %가 아니라 **ATR 배수**로 비교한다 — 값(%) ÷ ATR%. ATR은 `atrTimeframe`(기본 조건의 timeframe)의 `atrLookback`(기본 14)봉을 판단 시점(offset 0)에서 읽는다. 1분봉 조건에 `atrTimeframe: 60|1440`을 쓰면 시간·일 단위 변동폭으로 거리를 잰다. 비율·위치 피처와 ATR 피처에는 쓸 수 없다. 기본값을 명시한 것(`unit` 생략, `atrLookback 14`, `atrTimeframe` = 자기 시간대)은 같은 실행 해시다.

### 관리형 청산과 `ctExitStep`

`exit`는 두 모양 중 하나다. 고정형(`stopPct`, `targetPct`, `maxHoldBars`, `invalidation`)은 모든 엔진에서 그대로이고, 관리형은 `ct-pattern-3`에서만:

```
exit: { stop: {type: pct|atr|pattern_low|swing_low, value}, target?: {type: pct|atr|r, value},
        breakeven?: {triggerR, offsetPct?}, trail?: {type: pct|atr|swing_low, value, activateR},
        timeStop?: {bars, minR}, atr?: {timeframe, lookback}, maxHoldBars }
```

R = 초기 위험 = 진입가 − 초기 손절. `pattern_low`·`swing_low`의 `value`는 그 레벨 아래 여유폭(%)이다. 초기 손절이 진입가 이상이거나 15%보다 멀거나(또는 ATR·확정 스윙이 없으면) 그 신호는 **진입하지 않는다**(`blocked.invalid_stop`) — 추측한 손절로 거래하지 않는다.

**하나의 순수 함수**: `ctExitStep(spec, signal, position, bar, forced) → {position', exit | null}`을 `replayCT`, 모의·실전 러너(`ct-trading-engine.ts`), 설계 도구(손절·목표 격자, 청산 모드 비교)가 모두 쓴다. 러너의 손절가 인라인 재계산은 없앴고 `position.stopLevel`을 읽는다. 백테스트와 운용의 손절가가 갈라질 경로가 없다.

봉 안의 순서(보수적):

1. 그 봉 **이전에** 서 있던 손절을 먼저 검사한다(불리한 갭은 시가 체결, 손절·목표가 같은 봉이면 손절 먼저).
2. 목표, 시간 손절(`bars`번째 봉에서 한 번), 최대 보유(고정형 사유 `time`, 관리형 `max_hold`), 호출자가 넘긴 당일 경계 강제 청산(`day_end`/주식 `session`) 순이다.
3. 봉이 살아남은 뒤에만 그 봉의 고가로 `highestHigh`·본전·트레일을 갱신한다. 올라간 손절은 **다음 봉부터** 적용된다 — 같은 봉에서 트레일을 올리고 같은 봉 저가로 그 트레일에 걸리는 낙관·비관 혼합이 없다.

손절은 올라가기만 한다. 본전은 `+triggerR` 도달 시 `진입가 × (1 + offsetPct/100)`로, 트레일은 `+activateR` 도달 뒤 `pct`(최고가 × (1 − v)), `atr`(최고가 − v × 판단 시점 ATR), `swing_low`(진입 후 확정된 마지막 스윙 저점 × (1 − v), 5봉 중앙이 가장 낮을 때 확정)를 따른다.

**청산 사유**: `stop`, `breakeven`, `trail`, `target`, `time_stop`, `max_hold`(고정형은 `time`), `day_end`(주식 `session`), 구간 경계 `boundary`, 라이브에서 손절을 만들 수 없을 때 `invalid_stop`. 거래 기록(`CTTrade.management`: 초기 손절·목표·손절선 이동 이력, 고정형 거래에는 이 필드가 없다)과 차트(손절선 계단, 사유 라벨)에 남는다. 운용 거래는 `ctPosition`·`ctExitReason`을 거래 레코드에 저장한다.

**운용 상태**: 러너가 재시작하면 저장된 `ctPosition`에서 이어 가거나, 없으면 진입 봉부터 `ctRebuildPosition`으로 결정적으로 다시 계산한다. 두 방식이 같은 결과를 낸다는 테스트가 있다. 운용은 진입 봉(신호 봉이 닫힐 때 열리는 봉)부터 판단한다 — 백테스트가 진입 봉도 판단하는 것과 같다(이전에는 체결을 확인한 시각 이후 봉만 봤다).

**스트레스 "손절 ±10%"의 정의**: 고정형은 이전과 같이 `stopPct`에 ×0.9/×1.1(0.2–15%로 자름)을 적용한다. 관리형은 **초기 손절 거리**(`진입가 − 초기 손절`)에 ×0.9/×1.1(`replayCT`의 `stopScale` 옵션)을 적용하고 본전·트레일·시간 손절 파라미터는 그대로 둔다(R 목표는 그 R에 정의되어 있으므로 함께 움직인다).

### 설계 도구

- `query_conditional_returns`: 새 피처·`unit`·`entryWindows`를 받는다. `exitCompare`(선택)는 **같은 이벤트**를 고정 손절·R 목표 / 본전 이동 / 트레일(목표 없음) / 시간 손절로 나란히 돌려 행마다 이벤트 수, 승률, 평균 R, 비용 후 평균, 비용 2배 평균, 일평균(이벤트 합 ÷ 학습 일수; 겹침 무시한 상한 감각), 청산 사유 비율을 준다(학습 구간만, 손절 ≤ 3 × 목표 R ≤ 2 × 모드 3 + 트레일 ≤ 21행). 이벤트 목록과 청산 규칙은 `ctOpenPosition`+`ctExitStep` 그대로다.
- `screen_rule`은 새 spec을 받고 결과에 `freedom`(자유도)과 `multipleTesting`을 붙인다. `ctRuleText`는 새 요소를 한국어로 쓴다(고정형 규칙의 문장은 이전과 같다).
- `CT_DESIGNER_SYSTEM`: 새 어휘를 나열하는 데서 그치지 않고 각 어휘를 언제·왜 쓰는지 설명한다. "청산 구조로 비용을 이기는 방법"(R로 본 비용, 손실·이익의 비대칭, 변동성에 맞춘 손절, 본전·트레일·시간 손절의 이유)은 비용 장벽 설명 바로 뒤에 있다. 시스템 프롬프트와 도구 정의는 상수라 실행 중 바이트가 바뀌지 않는다(캐시 유지).

### 다중 검정 장부와 자유도

설계 세션의 모든 `query_conditional_returns`·`screen_rule` 호출을 **가설 서명**으로 센다: 단계별 `feature|timeframe|방향|단위`의 집합과 시간 창 사용 여부. 임계값·lookback·offset·maxGapBars·청산 숫자가 다른 변형은 같은 서명(1회), 다른 feature 조합·반대 방향·ATR 단위·시간 창은 새 검정이다. 연구 단위로 누적(`ct.tests`)하고,

- 설계자에게는 매 도구 결과에 `multipleTesting: {hypothesisTests, toolCalls}`로 짧게,
- 위험·증거 검토자에게는 `research.multipleTesting`(검정 수 + 후보 자유도)과 새 지시("검정 수 대비 개발·최종 결과의 유의성을 판단하라, 어휘가 늘었으니 단순한 규칙을 선호하라")로 전달한다.

후보의 **자유도** = 조건 수 + 청산 숫자(손절·목표·본전·트레일·시간 손절·최대 보유·ATR 설정) + 시간 창 끝점·진입 금지·ATR 단위 등 기타. 결과 요약(`screen_rule`, 이전 세션 후보 기록)과 검토 입력에 표시한다. 게이트는 바꾸지 않았다.

LLM은 수치 공간을 손으로 탐색하는 데 약하고 "이 패턴에 메커니즘이 있는가, 우연인가"를 판단하는 데 강하다. 그래서 **서버**가 거래할 가치가 있던 순간과 그 직전의 차이를 통계와 그림으로 정리하고, **설계자(Opus)**가 메커니즘을 판단하고 규칙으로 옮기고 스스로를 의심한다. 새 기능은 `policy.traderTools = 1`이 있는 **새 계약에서만** 켜진다. 이전 계약(턴 12·도구 24, 기존 4개 도구, 이전 지시문)은 바이트 단위로 그대로 돈다(`CT_DESIGNER_SYSTEM_STAGE2`의 SHA-256을 테스트가 고정). 게이트·롱 전용·당일 청산·1분봉·시간순 60/20/20·최종 구간 1회 평가는 바꾸지 않았다. **모든 새 도구는 학습 구간 전용**이고 앞을 내다보는 구간이 `trainingToMs`를 넘는 라벨·대조군·차트·거래는 버린다(자르지 않는다).

| `contrast_moves` | `labelId` + 피처 명세 ≤ 12개(feature·lookback·offset·timeframe·unit, 임계값 없음). 이벤트 대표 시점의 피처 분포와 **같은 시(하루 시작 후)·같은 달**에서 시드 고정으로 사건당 3개 뽑은 대조군의 분위수, 대조군 5분위별 이벤트 수·lift·z. `tree: true`면 깊이 ≤ 3 트리를 **앞 2/3 학습 일수**로 키우고(뒤 1/3 시작 뒤에 청산되는 순간은 제외) **뒤 1/3**에서 같은 잎의 lift·양성 비율·비용 후 평균을 다시 잰다(잎마다 라벨과 같은 청산 구조 하나를 가정). `contrastId`는 **같은 feature·timeframe을 측정한 조건**에 한해 근거 id로 인정된다. |
| `view_charts` | 서버가 발급한 시각만(이벤트·대조군·조회 앵커·`screen_rule` 거래 시각), 호출당 ≤ 8장, 세션 ≤ 32장. `blind: true`는 이벤트와 대조군을 같은 수로 섞어 무작위 순서·그룹 숨김으로 보여 준다. 이미지는 `tool_result`의 image 블록. |
| `grade_blind` | 블라인드 세트의 모든 차트에 positive/control 예측을 한 번에 제출 → 정확도와 **정확 단측 이항검정 p값**(세트가 균형이라 귀무가설은 50%). 세트는 한 번만 채점되고 채점 뒤 정답을 공개한다. 설계자의 "눈"이 이 시장에서 신호를 갖는지 스스로 확인하는 장치다. |
| `diagnose_trades` | `screen_rule`의 `screenId`(또는 후보 id)의 **학습 구간 거래**를 시간대·변동성 3분위·1시간 SMA20 위/아래·요일·보유 시간·청산 사유로 분해하고, 손실 거래 중 +1R(또는 왕복 비용 2배)에 한 번이라도 닿은 비율(**청산 문제**)과 비용만큼도 못 오른 비율(**진입 문제**), 이익 거래의 MFE 대비 실현 비율, 같은 진입에 다른 청산(원래 규칙·고정 2R·+1R 본전·+1R 트레일·시간 손절)을 `ctOpenPosition`+`ctExitStep`으로 적용한 결과, 필터 힌트를 준다. `diagnosisId`는 `range_pct`(1분)·`sma_distance_pct`(60분)에 한해 근거로 쓸 수 있고, 진단 필터를 쓴 후보는 `observedProblem`·`changes`에 부모 대비 변경을 적어야 한다. |

**사건 묶음 규칙**: 종목별로 시간순 스캔해 첫 양성 순간 i0에서 사건을 열고 i0의 거래가 목표에 닿는 봉까지 나오는 양성 순간은 같은 사건이다. 그다음 양성 순간부터 새 사건이다. 대표 시각은 사건 안 양성 순간들의 **중앙값 순간**의 봉 마감이다(첫 순간은 원인이 아직 보이기 전이고 마지막 순간은 이미 움직임 안이라서, 거래할 수 있었던 순간들의 한가운데를 쓴다).

**다중 검정 장부 합산**: `label_moves` 정의 1회, `contrast_moves`는 feature × 대조군 5분위마다 1회(라벨 정의가 다르면 다른 가설), `diagnose_trades`는 확인한 층 칸마다 1회, 블라인드 세트 채점 1회가 각각 서명으로 장부에 들어간다. 트리가 평가한 후보 분할 수는 서명이 아니라 `treeSplitsEvaluated`로 따로 보고한다. 도구 결과의 `multipleTesting`은 `conditionCombos`·`contrastCells`·`diagnosisCells`로 나뉘어 나온다.

### 차트 이미지

SVG를 그린 뒤 `@resvg/resvg-wasm`(WebAssembly, 네이티브 바이너리 없음, 어느 머신에서나 같은 바이트, Node·Workers 모두 가능)으로 PNG로 바꾼다. resvg-wasm은 텍스트를 렌더링하지 못하므로 글자는 `@pdf-lib/fontkit`으로 `assets/fonts/NotoSans-Regular.ttf`(OFL)의 윤곽을 벡터 경로로 그린다(시스템 폰트 무관). 한 장 1,420 × 456px, PNG 약 65KB, 렌더 약 0.2초, 입력 약 860–1,100토큰. 왼쪽 최근 5일 1시간봉(+전일 고가·저가), 가운데 당일 5분봉(VWAP·시가 범위 첫 30분 박스·전일 고가·저가·종가), 오른쪽 앵커 직전 90분 1분봉 + 거래량. **앵커 이후 봉은 읽지도 않는다**(앵커 뒤를 오염시켜도 PNG가 비트 단위로 같다). 축은 가격이 아니라 **앵커 종가 대비 %**, 날짜는 없고 시각만 있다. 이미지 base64는 세션 메시지(`ct_session_messages`)에 그대로 저장되어 이후 턴 요청에 바이트 그대로 다시 실리고(캐시 읽기 유지), 화면용 사본은 `ct_chart_images`에 있다. 비용 예약과 실시간 추정은 base64 글자 수가 아니라 이미지당 약 1,100토큰으로 센다(`lib/designer-request-size.ts`).

### 플레이북 (`lib/ct-playbook.ts`)

시장 단위 누적 기억이다. `ct_playbook`(아이디어 하나 = 한 행: 시장·종목·주기·메커니즘·조건 구조(feature·timeframe, 임계값 제외)·검증 방식·결과 등급·사유·**측정 기간**·비용 프로필·엔진·실행 id)과 `ct_playbook_runs`(실행별 가설 검정 수 = 누적 검정 수의 원천). 연구가 끝날 때(정상 종료·통과·탈락 모두) 설계 세션의 `rejectedHypotheses`(`rejected_in_training`), 학습 게이트 탈락 후보(`screen_failed`), 개발 결과(`development_failed`), 최종 구간을 연 후보(`passed_final`/`failed_final`)를 기록한다. 같은 실행을 두 번 기록해도 같다(결정적 id). 이 작업 이전에 끝난 실행은 처음 읽을 때 한 번 소급 기록한다(`source: backfill`). 시드는 `docs/research/results-2026-09.md`의 가설 10개(`timeframe: daily`, `comparable: false` = 단타와 직접 비교 불가; H2만 `adopted_daily`, 나머지는 `development_failed`)이며 주식 시장 항목이고 1분봉 누적 검정 수에는 섞지 않고 `dailyTests`로 따로 보여 준다.

**누출 규칙**: 항목의 측정 기간이 **새 연구의 개발·최종 구간**(`[trainingToMs, toMs]`)과 겹치면 메커니즘과 결과 등급·사유만 보여 주고 `detail` 수치를 빼며 자유 서술 사유의 숫자도 `#`로 가린다. 새 연구의 학습 구간 안에서만 측정된 항목은 수치를 보여 준다. **최종 구간 성과는 어디에도 저장하지 않는다**(테스트: 최종 수익률 99.9를 넣은 실행을 기록해도 저장된 어떤 행에도 없음). 기존 `ctMemory`도 같은 규칙을 따른다(겹치면 `netReturnPct: null`). 설계 세션 안정 블록(캐시)에는 같은 시장 최근 40개(1분봉 먼저), 이전 실행 수, **누적 검정 수**가 들어가고 실행 시작 때 한 번 고정되어(`playbook_summary` 도구 캐시) 재개해도 같다. 위험·증거 검토자에게는 누적 검정 수(이 실행 + 이전 실행)와 플레이북 항목, 라벨·contrast·차트·블라인드 결과·진단 요약, 후보의 `selfRebuttal`이 가고 지시에 "이미 기각된 메커니즘의 변형인가, 누적 검정 수를 고려해도 개발 결과가 의미 있는가"가 들어 있다. CT 화면의 「플레이북」 섹션(접이식)이 읽기 전용 목록과 등급·주기·검색 필터를 보여 준다.

### 설계자의 작업 순서와 한도

`CT_DESIGNER_SYSTEM`을 "단타 고수의 작업 순서"로 다시 썼다(단계를 강제하지 않고 이유를 설명한다): ① 판 읽기(비용 장벽·플레이북·누적 검정 수) → ② 거래할 가치가 있던 순간 보기(`label_moves`, `view_charts`) → ③ 직전의 차이 찾기(`contrast_moves`, 블라인드 보정) → ④ 메커니즘과 반증 조건 → ⑤ `query_conditional_returns`로 확인 → ⑥ 청산 모드 비교 → ⑦ `screen_rule`·`diagnose_trades` → ⑧ **제출 전 자기 반박**: 새 필드 `selfRebuttal`(우연일 가장 그럴듯한 이유 3개 이상, 각각의 배제 방법과 `excluded: yes|partly|no`)을 새 계약의 모든 제출 후보에 요구한다. `contrast_moves`의 lift는 단서일 뿐 성과 근거가 아니며 최종 확인은 `query_conditional_returns`·`screen_rule`로 한다.

한도(새 계약): 세션당 모델 턴 **16**, 도구 호출 **40**, `screen_rule` 6, 차트 이미지 **32장**, 블라인드 세트 **2**. 이전 계약은 12/24/6, 이미지 없음. 진행 화면은 새 도구를 "지금 하는 일"과 피드에 표시하고, 세션 섹션에 이벤트 수·최대 lift·본 차트 썸네일·보정 정답률(p)·복기 요약(손실 중 +1R 도달 % / 수익권 미도달 %)·가설 검정 수를 보여 준다(`traderSummary`, `lib/ct-activity.ts`).


### 엔진 버전 (`ct-pattern-2`까지)

`ct-pattern-1`은 이전 DSL(1/3/12, 보유 ≤ 390, 코인 연속)이고 `ct-pattern-2`가 새 규칙(60/240/1440, 보유 ≤ 1,440, `noEntryBeforeDayEndMinutes`, 당일 강제 청산)이다. 명세는 계약의 엔진과 같아야 하고(`validateCTSpec`), `ct-pattern-1` 명세가 새 기능을 쓰면 스키마가 거부한다. 도구 캐시 키는 계약의 엔진을 포함하므로 이전 실행을 재개해도 같은 도구 결과를 재사용한다.

## 사용 흐름

1. CT에서 시장을 선택하고 **전략 생성**을 누른다. 기본 연구 비용 상한은 $8다.
2. 연구 중에는 화면 상단에 고정되는 상태바(단계 n/11, 경과, 후보, 백테스트, 비용 미터, 러너, 일시정지/재개/취소)와 **지금 하는 일** 패널, 단계 스테퍼, 최신 후보 카드, 활동 피드로 진행을 추적한다. 지금 하는 일 패널은 현재 작업 주체(모델 호출이면 역할·모델·설계 세션·턴·경과·실시간 입력(캐시 읽기 포함)/출력 토큰과 출력 한도·호출 비용, 서버 도구면 어떤 백테스트/조회/원문 읽기인지, 일시적 오류면 원인과 재시도까지 남은 시간)와 연구에 참여하는 6개 에이전트(서버 엔진, 총괄, 자료 분석, 연구·설계, 독립 위험 검토, 독립 최종 검토)의 상태·호출 수·비용을 보여 준다. 옛 실행의 역할명(`designer` 등)도 같은 에이전트로 표시한다. 설계 세션 섹션은 세션별 턴·도구·조회 목록, 기각 가설, 학습 게이트 탈락 후보를 보여 준다. 새 기록이 없으면(모델 호출 5분, 그 외 45초, 재시도 예정 시각 + 45초) 멈춤으로 표시한다. 활동 피드는 도구 호출과 모델 호출을 한 시간순으로 보여 준다. 실시간 토큰은 이 탭이 진행하면 `advance` NDJSON 스트림의 `usage`에서, 러너가 진행하면 약 2초마다 저장되는 `strategy_generation_meters`(`GET`의 `liveMeter`)에서 온다. 연구가 실행 중이면 2초, 아니면 5초마다 폴링하고 백그라운드 탭에서는 멈춘다. 판정 로직은 `lib/ct-activity.ts`(테스트 `tests/ct-activity.test.mjs`)에 있다. 가설 설계, 실제 실험과 수정 이력을 확인하고 도구 결과는 개별 다운로드할 수 있다.
   생성 작업은 계정 전체에서 동시에 1개만 `running`이다(`idx_generation_active`). 다른 브라우저 세션·전략 탭·CT 코인/주식에서 시작한 작업이 슬롯을 잡고 있으면 CT·전략 화면이 시작 버튼 위에 그 작업(종류·단계·시작/갱신 시각·비용)과 **취소 버튼**을 표시한다(`GET`의 `blocking`, `POST action: cancel_blocking`). 소유자 쿠키는 http 로컬 주소에서는 `Secure` 없이 발급한다. 막고 있는 작업이 2분 넘게 갱신되지 않고 러너도 꺼져 있으면 멈춤 경고와 연구 러너 실행 명령을 함께 보여 준다. 소유자는 `QQUAN_OWNER_ID`가 설정되면 모든 브라우저에서 같은 값이다(로컬 `.dev.vars` 기본). 설정이 없을 때만 브라우저 쿠키가 소유자이며, 이때 다른 브라우저 세션에서 시작한 작업의 세부 진행은 노출하지 않는다.
3. 독립 검토와 동결된 최종 평가를 모두 통과한 경우에만 **전략 등록**이 가능하다. 통과 후보가 없으면 정상적으로 종료하며 등록 버튼이 생기지 않는다.
4. 등록한 버전으로 모의 대시보드를 시작한다. 연구 완료는 매매 시작을 뜻하지 않는다.
5. 실전은 같은 해시의 전향 모의 거래 20건 이상, 비용 후 양수 성과, 러너 온라인, 계좌/잔고/권한 확인, 명시적 시작 확인을 요구한다. Upbit는 `UPBIT_TRADING_DISABLED=false`도 필요하다.
6. 정지는 미체결 매수 취소 → 소유 포지션 청산 → 체결 대사 순서다. 러너를 종료하는 것만으로 청산되지 않는다.

새 연구나 새 등록이 기존 실행을 변경하지 않는다. 시작할 때 가장 최근에 명시적으로 등록한 한 버전과 연구 자본을 고정한다. 다른 전략을 적용하려면 기존 운용을 정지하고 다시 시작한다. 한 실행 장부는 동시에 한 포지션만 가진다.

## 설계 세션 (2026-10-13)

`design`/`reflect` 단계는 `generationCall` 1회가 아니라 **설계 세션**이다. 한 번의 진행(advance)마다 모델 턴 하나 또는 그 턴의 도구 실행 묶음 하나를 처리하고 저장한다.

**세션 시작 컨텍스트**(도구 호출 없이, 안정적인 것부터): 시스템 지시(역할·목적 함수·DSL·과최적화 규칙, `CT_DESIGNER_SYSTEM`) → 고정 블록(계약·비용·게이트·한도, 비용 장벽 표, `ctAnalyst` 원리 요약과 출처 id·제목·URL, 허용 기억의 규칙 텍스트) → 이전 세션 기록(조회 목록, 기각 가설, 후보별 규칙 텍스트와 학습·개발·스트레스 핵심 수치·탈락 사유; 전체 spec JSON은 부모로 지정 가능한 개발 실험 후보만; 세션 사이에 뒤에만 추가) → 이번 세션 안내와 사용자 brief. 원문 전문과 원시 가격 CSV는 넣지 않는다.

**비용 장벽 표 `cost_hurdle`**: 학습 구간 5봉마다 다음 봉 시가 진입을 가정해 보유 5/15/60/240/390봉의 MFE/MAE 분위수(p10–p90)와 MFE가 왕복 비용의 1·2·3배를 넘는 비율을 계산한다. 시간대(코인 UTC 4구간, 주식 개장 60분·장 중반·마감 60분)와 직전 60봉 범위 3분위 변동성 국면으로 나눈 표와 한 줄 결론을 붙인다. 왕복 비용은 `replayCT`와 같은 `ctNetTradePct` 공식이다(BTCUSDT 계약 0.3095%, 비용 2배 0.618%).

**도구**(모두 학습 구간 전용·서버 계산·무료, `tool()`을 거쳐 `ct_tools`에 캐시되어 재개 시 재계산하지 않음):

| 도구 | 내용 |
| --- | --- |
| `query_conditional_returns` | DSL 조건 그대로의 1–4단계 시퀀스로 이벤트를 찾는다(`detectCT`를 `replayCT`와 같은 이력 창·feature 캐시로 호출). 보유 시간별(최대 5개) 총수익 분위수, 비용 후 평균·중앙값·비용 2배, MFE/MAE, 같은 시간대 구성의 무조건 기준선 대비 차이, 손절·목표 격자(최대 4×4, `ctExit` 그대로) 목표 먼저/손절 먼저/시간 청산 비율과 비용 후 기대값, 월별 이벤트·기대값, `read_bars` 기준 시각. 앞을 내다보는 구간이 `trainingToMs`를 넘는 이벤트는 버린다. 결과의 `queryId`가 근거 id다. |
| `read_bars` | 서버가 제공한 시각(조회 대표 이벤트, 부모 후보·사전 검사의 학습 거래 시각)만 최대 4개, 앞뒤 합계 240봉. 첫 시가 대비 bp 정수 o/h/l/c, 구간 중앙값 대비 거래량 배수, 시각은 첫 줄과 30봉마다. |
| `screen_rule` | 완성 spec을 `validateCTSpec` 후 학습 구간만 `replayCT`로 돌려 `ctSummary`와 `ctGate` 사유를 돌려준다. 개발 결과는 돌려주지 않는다. 이 리플레이는 실험 단계의 학습 백테스트와 같은 캐시를 쓴다. |
| `submit_candidates` | 후보 0–3개와 `noEdgeReason`, `rejectedHypotheses`. 서버가 zod·명세·근거를 다시 검증하고 실패하면 `is_error` tool_result로 같은 세션에서 고치게 한다. 후보 0개는 「통과 전략 없음」 정상 종료(최종 구간 미개봉). `strict: true`는 실제 API가 400 "compiled grammar is too large"로 거부해(2026-10-13 측정, 비용 $0) 쓰지 않는다. 어떤 도구도 strict가 아니며 서버 zod 검증이 그 역할을 한다. |

**한도**(`CT_POLICY`, 이전 계약에 없으면 현재 값): 세션당 모델 턴 12회, 도구 호출 24회, `screen_rule` 6회, 연구당 세션 3회. 계산 시간은 기존 `maxComputeMs`(600초)를 공유한다. 마지막 턴 직전(턴·도구 한도 또는 예산 여유가 턴 예약의 2배 미만)에 "지금 제출하라"는 안내를 tool_result 뒤에 붙인다. `tool_choice`는 강제하지 않는다(`auto`). 그래도 제출하지 않으면 세션을 실패로 기록하고, 실패 2회 또는 세션 한도면 「통과 전략 없음」으로 끝낸다. 후보 한도 6은 **제출된(중복 제거 후) 후보 수**로 센다. 정체·중복 한도 규칙은 유지한다. 활성 작업 한도는 짧은 Opus 턴이 많아져 1,800초에서 3,600초로 늘렸다(새 계약부터).

**근거 규칙(근거 버전 2)**: `spec.sourceIds`·`mapping[].sourceId`는 근거 id다 — 확인된 웹 출처 id, 또는 이 실행에서 완료된 학습 구간 `query_conditional_returns`의 `queryId`. 조회 근거는 그 조회가 같은 feature와 같은 `timeframe`을 실제로 측정했을 때만 인정한다(lookback·임계값 차이는 `implementationAssumption`에 적는다). 존재하지 않는 id, 다른 실행의 id, 학습 구간 밖 조회는 거부한다. 수락된 후보에 `evidenceVersion: 2`가 붙고, 필드가 없는 옛 후보와 등록 패키지는 웹 출처 규칙으로 계속 읽힌다. 부모가 있으면 실측 문제·변경·기대 효과가 필요하고, 새 메커니즘은 `parentId: null`로 낸다.

**요청 형태(Opus 5.5)**: `thinking: {type: "adaptive"}`, `output_config.effort: "high"`(기본 medium이므로 명시), `tool_choice: auto`, temperature·budget_tokens 없음, 스트리밍 후 `finalMessage()`. 캐시 지점은 시스템 프롬프트(앞에 렌더링되는 도구 정의 포함), 첫 메시지의 고정 블록 끝, 최상위 자동 캐시(최신 블록) 3개다. assistant `content`(thinking 블록·서명 포함)는 수정 없이 다음 요청에 그대로 붙인다. `refusal`·`max_tokens`는 기존 `IncompleteResponseError` 경로이고, 절단은 한도 64,000토큰·effort medium으로 1회 재시도한다.

**내구성·비용 장부**: 세션의 모델 턴 하나하나가 `ask()`와 같은 `paidCall` 장부를 거친다 — 호출 전 턴 단위 예약(입력은 캐시 쓰기 단가, 출력은 턴 한도), `job.calls` 기록, 실시간 미터, 완료 응답 재사용 키(실행 id·세션·턴·직전 메시지 해시), 중단 시 미확인 비용, 절단 재시도. 메시지 기록은 `ct_session_messages(run_id, session, seq)`에 한 행씩 append-only로 저장하고(`strategy_generation_runs.payload`에는 참조만), 러너가 죽어도 저장된 턴부터 이어 이미 지불한 턴을 다시 사지 않는다. 취소 후 늦게 온 응답은 저장되지 않는다. 검토 예비 예산(`reserveFraction` 35%)은 유지하며, 새 세션은 턴 예약 3배 이상의 여유가 있을 때만 연다.

## 실행 명세와 동일 코드 계약

`ct-pattern-1`·`ct-pattern-2`의 JSON DSL만 실행한다(계약의 엔진과 명세의 엔진이 같아야 하고 새 연구는 `ct-pattern-2`). 한 패턴은 시간순 1–4개 단계, 단계마다 AND 조건 1–6개와 단계 간 최대 봉 수로 구성된다. feature는 수익률, SMA 거리, 가격 범위, 상대 거래량, 변동성 수축 비율, 이전 고점/저점 거리, 범위 내 위치, 확정 스윙 고점/저점 거리이고 `ct-pattern-3`에서 VWAP·전일 고저종·당일 시가·시가 범위·당일 고저 위치와 ATR 피처가 더해진다(위 「단타 트레이더의 어휘」). lookback/offset은 과거의 2–120/0–120봉, 시간배수는 1/3/12(1분 기준 1/3/12분 완성 봉)와 `ct-pattern-2`의 60/240/1440(위 「관찰 창」)이다. 최대 보유는 주식 390봉(정규장 한 세션), 코인 `ct-pattern-2`는 1,440봉이며 어느 쪽이든 포지션은 당일 경계에서 닫힌다. 2026-10-13 이전 엔진은 상위 봉 묶음의 연속성을 상위 봉 크기로 비교해 시간배수 3/12 조건이 항상 null이었다. 수정 후에야 실제로 평가된다. 스윙은 오른쪽 2봉 이후에만 확정한다. 상위 봉은 완성된 봉만 사용한다.

진입 유효기간, 최대 스프레드/괴리, 손절/목표/시간 청산(`ct-pattern-3`: 본전·트레일·시간 손절·R 목표), 진입 시간 창, 마지막 단계 저점 무효화, 위험/배분/거래량 참여 한도, 쿨다운을 수치로 고정한다. 롱 현물/주식만 지원한다. 추세선 작도, 자유 코드, 임의 지표, 숏/레버리지, 재량 판단은 지원하지 않는다. 표현할 수 없는 조건은 설명에만 넣어 통과시킬 수 없다.

`lib/ct-engine.ts`의 `detectCT`, `ctExitStep`(고정형 청산의 `ctExit`와 같은 판정), `ctQuantity`를 백테스트와 모의/실전이 공유한다. 실시간 판단 경로에는 모델/연구 실행기 호출이 없다. 거래마다 시작 당시 spec/hash와 실제 신호 관측값을 저장한다. 이름·설명만 다른 동일 규칙은 정규화 해시로 탐지한다. 실제 실행 전에도 승인 해시를 확인한다.

## 검증과 시장 차이

기본 데이터는 최근 180일, 시간순 60% 학습 / 20% 개발 / 20% 최종이다. 각 경계에서 필요한 이력을 다시 확보하며 이전 구간 신호/포지션을 넘기지 않는다. 최소 500봉이 없거나 비정상/중복 가격이 있으면 보류한다. 동일 시장·겹치는 종목·겹치는 최종 기간을 다른 연구에서 다시 열지 않는다. 원문과 모델 사전학습이 과거 기간을 몰랐다고 주장하지 않는다.

백테스트는 완성 봉 이후 다음 봉 진입, 비용/스프레드/슬리피지, 거래량 참여, 최소 주문, 수량 정밀도, 신호 만료와 미체결을 반영한다. 같은 봉에서 손절/목표가 모두 닿으면 손절을 먼저 적용하고 불리한 갭은 시가로 처리한다. 보유 중 봉이 누락되면 `data_error`이며 낙관적 청산을 만들어내지 않는다. 무거래, 데이터 오류, 실행 실패, 전략 기준 미달을 구분한다. OHLCV 참여율 제한은 실제 과거 호가/대기열/부분체결 복원이 아니다. 모의는 현재 호가에서 전량 체결하는 단순 모델이고 실전은 실제 누적 부분체결을 대사한다. 이 차이는 검토와 전향 모의 요구에 포함된다.

서버 게이트는 거래 20건 이상, 비용 후 양수 수익, **일평균 비용 후 순수익 > 0**, 최대 낙폭 15% 이내, 규칙 준수 100%, 종목/월 집중도 제한이다. 일평균은 평가 구간의 모든 날(주식은 뉴욕 기준 거래일, 코인은 UTC 날짜)의 일별 순수익률 평균이며 무거래일은 0으로 넣는다. 수수료·세금·스프레드·슬리피지를 모두 뺀 값이다. 비용 2배·1봉 지연·손절 민감도도 총수익과 일평균이 모두 양수여야 통과한다. 이 필드가 없던 과거 결과는 저장된 일별 행에서 다시 계산한다. 목표 수익은 게이트와 별개다. $8/$16/$24 예산 안에서 유료 호출 전에 예약하며 웹 검색 요금은 중앙 모델 비용 설정을 사용한다. 후보 최대 6개(제출 기준), 설계 세션 최대 3회, 개발 실험 묶음 최대 12개, 누적 계산 600초(1분봉 BTC 180일은 약 26만 봉), 활성 작업 3,600초(이전 계약 1,800초), 개선 정체 3회에서 정상 종료한다. 리뷰 예산을 미리 남긴다.

주식은 현재 종목 선택의 생존/선택 편향을 표시한다. 과거 구성 종목 복원이나 수정주가 복원이 아니다. 연구 원봉은 Massive adjusted=false이며 연속 세션 안에서만 패턴 이력을 사용한다. 집계는 UTC 격자이므로 60분 주식 봉은 정규장 첫 30분을 완성 60분 봉으로 만들지 않는다. 알려진 NYSE 2025–2028 휴장/조기 폐장만 버전 관리하며 그 밖의 연도는 거부한다. 긴급 폐장/거래정지/기업행사와 실전 IP 제약은 별도 한계다.

차트는 엔진의 패턴 구간, 조건값, 실제 사용 기준선, 확정 스윙, 신호/진입/손절/목표/청산과 거래량을 표시한다. 리플레이에서는 알려진 시점 이후만 선/표식을 보여준다. 수익·손실 대표 사례를 함께 선택하고 모든 연구 거래는 도구 결과 다운로드에서 확인한다. 운용 대시보드의 보유/거래 기록에서 개별 거래 차트를 열 수 있다. `ct_trade_charts`는 당시 관측한 봉과 실제 신호·체결·동결 해시를 별도 보존하므로 최신 시세 캐시가 사라져도 근거가 남는다. 최대 480봉(긴 운용은 처음 200/마지막 280봉)을 저장하며, 수정된 과거 봉은 원본을 덮어쓰지 않고 오류로 기록한다. 차트 저장 장애는 주문 감시/청산을 막지 않고 이벤트로 남긴다. 의도/근거 저장 중 만료된 매수 신호는 전송 직전에 다시 차단한다. 20봉 참고 고점/저점은 전략이 사용한 돌파선이라고 표시하지 않는다.

## 저장, 재개와 운용 안전성

기존 `strategy_generation_runs`에 CT 상태를 저장한다. `ct_data_pages`는 페이지 체크포인트, `ct_tools`는 완료 도구 응답, `ct_session_messages`는 설계 세션 메시지(append-only), `ct_replay_pages`는 전체 거래 기록, `ct_exposure`는 최종 기간 소진, `ct_strategies`는 등록 패키지, `ct_runtime`은 연구 러너 heartbeat, `ct_trade_charts`는 실제 운용 거래의 관측 봉과 규칙/체결 근거다. 큰 거래 목록은 별도 페이지에 저장하고 상태에는 대표 사례와 실제 총 거래 수를 남긴다.

브라우저/러너는 기존 DB lease로 같은 작업을 중복 실행하지 않는다. 완료 유료 응답과 도구 응답은 단계 저장 실패 후에도 재사용한다. 취소 후 늦게 온 응답은 상태/등록을 변경하지 못한다. 연구 기억은 동일 소유자·시장·주기·종목·비용·자본·엔진으로 제한하고 이전 개발 구간 결과만 전달한다.

장부는 `relay`, `surge`, `ct-stock`, `ct-crypto` × paper/live로 분리한다. 실계좌는 장부별 가상 잔액으로 격리됐다고 가정하지 않는다. 브로커 단위 DB 잠금, 실제 주문 가능 잔고/미체결, 소유 수량을 함께 검사한다. 다른 장부 미체결 매수의 잔여 수량 × 지정가 × 1.01 예약액을 추가 차감한다. 브로커가 이미 차감했다면 보수적으로 이중 예약되어 진입 가능 금액이 줄어들 수 있다. 주문 의도/identifier를 먼저 저장하고 응답 유실은 조회/대사한다. Upbit는 identifier로 복구하며 Toss가 client ID를 조회에 제공하지 못하는 경우 자동 재주문하지 않고 대기한다. 미확정 주문은 신규 진입과 정지 완료를 차단한다. 신호 만료, 오래된 호가, 손실 한도, 단일 포지션, 다른 장부 미확정 주문도 신규 진입을 차단한다.

브라우저를 닫은 뒤에는 상시 머신의 러너가 필요하다. 메모리 타이머는 영구 실행기로 쓰지 않는다. 연구 loop와 주문 감시 loop는 분리되어 있다. 연구 러너가 없으면 화면에 대기를 표시한다.

```sh
# .dev.vars는 서버 비밀이며 Git에 포함하지 않는다.
node --env-file=.dev.vars scripts/trading-runner.mjs --url http://localhost:3000
# 연구만 검증: 주문 감시 tick을 보내지 않는다.
node --env-file=.dev.vars scripts/trading-runner.mjs --generation-only
```

원격 실행에는 서버와 러너에 같은 `STRATEGY_RUNNER_SECRET`을 설정한다. Sites 원격 실행에서는 기존 사이트의 접근 정책에 맞는 인증을 확인한다. 요청이 실제 주문을 보내는 위치는 러너 머신이 아니라 대상 앱 서버이므로 Toss/Upbit의 허용 IP도 앱 서버 출구 IP여야 한다. 러너가 꺼지면 자동 매매 감시가 지속된다고 표시하지 않는다.

Upbit BTC/ETH 각 4,317개 완성 60분 봉, 44페이지와 실제 공개 검색/원문 읽기, 완료 모델 호출 7회, 후보 5개, 실제 리플레이 30회를 사용했다. 비용은 $0.5062536/$8이었다. 개선 정체에 따라 **통과 전략 없음**으로 정상 종료했고 최종 기간은 열지 않았다. 임의 성과나 임의 등록은 없었다. 요약은 [검증 기록](ct-evaluation-2026-10-12.json)에 있다. 이 기록은 실행 도중 저장된 엔진 산출물이며 이후의 비용 보고/차트 표시 개선을 적용해 과거 결과를 재작성하지 않았다.

실제 Upbit 현재가/호가/계좌 읽기와 Toss SPY 15분 연구의 원봉 4페이지 수집도 확인했다. 실제 주문은 0회다. 전체 주식 연구, 실제 통과 후보의 독립 검토/최종 평가/등록, 전향 모의 체결, 실전 주문은 실데이터 통합 검증되지 않았다. 통과→독립 검토→최종 동결→등록→동일 규칙 실행, 유실 응답/부분체결/취소 순서는 고정 모델 응답과 합성 데이터 테스트로 구분해 검증한다. 한 연구의 성과를 일반 수익성의 증거로 사용하지 않는다.

기본 연구 실행은 로컬 Node + SQLite + Parquet다. 웹사이트 변경의 호스팅 배포 대상은 Sites이며, [배포 문서](deployment.md)에 따라 기존 프로젝트의 빌드·D1 연결·API 동작을 검증한다. 로컬 연구 DB와 시장 파일은 Sites에 자동 이전되지 않는다. 과거 Vercel용 Node/Nitro 및 D1 REST 어댑터 구성은 기본 배포 완료 기준이 아니다.
