# CT — Chart Trading

투자 메뉴는 전략 → CT → 급등주 순서다. CT의 주식/코인 선택과 투자 메뉴 선택은 기기에 기억된다. 주식은 기존 Toss 미국 현금 주식, 코인은 Upbit KRW 현물이다. 기본값으로 전략 생성을 시작할 수 있다. 연구 방향, 1–4개 종목, 자본, 연구 비용은 선택 설정이다. 봉 주기는 선택할 수 없다: 새 연구는 항상 **1분봉**으로 설계·백테스트한다(2026-10-13). 이전에 등록된 5/15/60분 패키지는 그대로 유효하다.

## 현재 로컬 데이터 정책 (2026-10-13)

기본 연구는 주식 **NVDA / Massive raw 1m**, 코인 **Binance Spot BTCUSDT / USDT 1m**다.
Settings에서 공유 Parquet 데이터를 먼저 다운로드한다. CT는 로컬 coverage를 사전 검사하고
불변 파일 snapshot/version을 고정하며, 연구 중 과거 시세 API를 호출하지 않는다.
NYSE 캘린더는 2020–2035로 확장했다. NVDA 원주가 분할 경계는 세션 격리로 처리한다.
Binance USDT 연구의 Upbit KRW 실행은 차단한다. 기존 Upbit 기록·포지션 청산은 보존한다.
아래의 기존 실행 검증/저장 기록 중 Upbit, 연구별 수집, 2025–2028 캘린더 설명은 과거 버전 기록이다.
현재 실행 명령과 정책은 [로컬 실행 문서](local-runtime.md)를 따른다.

## 사용 흐름

1. CT에서 시장을 선택하고 **전략 생성**을 누른다. 기본 연구 비용 상한은 $8다.
2. 연구 중에는 화면 상단에 고정되는 상태바(단계 n/11, 경과, 후보, 백테스트, 비용 미터, 러너, 일시정지/재개/취소)와 **지금 하는 일** 패널, 단계 스테퍼, 최신 후보 카드, 활동 피드로 진행을 추적한다. 지금 하는 일 패널은 현재 작업 주체(모델 호출이면 역할·모델·설계 세션·턴·경과·실시간 입력(캐시 읽기 포함)/출력 토큰과 출력 한도·호출 비용, 서버 도구면 어떤 백테스트/조회/원문 읽기인지, 일시적 오류면 원인과 재시도까지 남은 시간)와 연구에 참여하는 6개 에이전트(서버 엔진, 총괄, 자료 분석, 연구·설계, 독립 위험 검토, 독립 최종 검토)의 상태·호출 수·비용을 보여 준다. 옛 실행의 역할명(`designer` 등)도 같은 에이전트로 표시한다. 설계 세션 섹션은 세션별 턴·도구·조회 목록, 기각 가설, 학습 게이트 탈락 후보를 보여 준다. 새 기록이 없으면(모델 호출 5분, 그 외 45초, 재시도 예정 시각 + 45초) 멈춤으로 표시한다. 활동 피드는 도구 호출과 모델 호출을 한 시간순으로 보여 준다. 실시간 토큰은 이 탭이 진행하면 `advance` NDJSON 스트림의 `usage`에서, 러너가 진행하면 약 2초마다 저장되는 `strategy_generation_meters`(`GET`의 `liveMeter`)에서 온다. 연구가 실행 중이면 2초, 아니면 5초마다 폴링하고 백그라운드 탭에서는 멈춘다. 판정 로직은 `lib/ct-activity.ts`(테스트 `tests/ct-activity.test.mjs`)에 있다. 가설 설계, 실제 실험과 수정 이력을 확인하고 도구 결과는 개별 다운로드할 수 있다.
   생성 작업은 계정 전체에서 동시에 1개만 `running`이다(`idx_generation_active`). 다른 브라우저 세션·전략 탭·CT 코인/주식에서 시작한 작업이 슬롯을 잡고 있으면 CT·전략 화면이 시작 버튼 위에 그 작업(종류·단계·시작/갱신 시각·비용)과 **취소 버튼**을 표시한다(`GET`의 `blocking`, `POST action: cancel_blocking`). 소유자 쿠키는 http 로컬 주소에서는 `Secure` 없이 발급한다. 막고 있는 작업이 2분 넘게 갱신되지 않고 러너도 꺼져 있으면 멈춤 경고와 연구 러너 실행 명령을 함께 보여 준다. 소유자는 `QQUAN_OWNER_ID`가 설정되면 모든 브라우저에서 같은 값이다(로컬 `.dev.vars` 기본). 설정이 없을 때만 브라우저 쿠키가 소유자이며, 이때 다른 브라우저 세션에서 시작한 작업의 세부 진행은 노출하지 않는다.
3. 독립 검토와 동결된 최종 평가를 모두 통과한 경우에만 **전략 등록**이 가능하다. 통과 후보가 없으면 정상적으로 종료하며 등록 버튼이 생기지 않는다.
4. 등록한 버전으로 모의 대시보드를 시작한다. 연구 완료는 매매 시작을 뜻하지 않는다.
5. 실전은 같은 해시의 전향 모의 거래 20건 이상, 비용 후 양수 성과, 러너 온라인, 계좌/잔고/권한 확인, 명시적 시작 확인을 요구한다. Upbit는 `UPBIT_TRADING_DISABLED=false`도 필요하다.
6. 정지는 미체결 매수 취소 → 소유 포지션 청산 → 체결 대사 순서다. 러너를 종료하는 것만으로 청산되지 않는다.

새 연구나 새 등록이 기존 실행을 변경하지 않는다. 시작할 때 가장 최근에 명시적으로 등록한 한 버전과 연구 자본을 고정한다. 다른 전략을 적용하려면 기존 운용을 정지하고 다시 시작한다. 한 실행 장부는 동시에 한 포지션만 가진다.

## 내부 연구 에이전트

기존 `strategy-generation` 실행기의 비용 예약/사용량, 응답 캐시, 작업 잠금, 체크포인트, 취소/재개와 독립 회사 검토를 재사용한다. 슬롯 선택기를 복제하지 않았다. CT는 전략 탭과 별도의 CT 전용 역할(`CT_MODELS`)을 쓴다(2026-10-13).

| CT 역할 | 모델 | 하는 일 |
| --- | --- | --- |
| `ctOrchestrator` | OpenAI `gpt-6.1-sol` · medium | 공개 접근법 웹 검색(선택 사항). `prompt_cache_key`는 실행 ID |
| `ctAnalyst` | OpenAI `gpt-6-luna` · low | 읽은 원문에서 원리·인용·근사·재량 요소 추출 |
| `ctDesigner` | Anthropic `claude-opus-5-5` · adaptive thinking · effort high | **설계 세션**: 학습 구간 측정 도구로 가설을 세우고 검증한 뒤 후보 0–3개 제출 |
| `ctRiskReviewer` | OpenAI `gpt-6.1-sol` · high | 동결 규칙의 누출·과최적화·**데이터 스누핑/다중 검정** 검토 |
| `ctEvidenceReviewer` | OpenAI `gpt-6.1-sol` · high | 최종 평가 증거·수치 게이트·다중 검정 확인 |

검토자는 후보를 쓴 역할과 다른 회사여야 한다(`assertDifferentProvider`, `ctReviewRoles`). 이전 실행의 후보(옛 `designer`, OpenAI)는 옛 검토 역할(Anthropic)로 검토된다. Anthropic 장애 대체는 같은 회사의 `claude-sonnet-5-5`뿐이다. 새 CT 연구 생성 시 CT가 실제로 쓰는 모델만 접근을 사전 확인한다.

### 왜 바꿨는가 (기준 실행 `9a3c8627`, BTCUSDT 1분봉, 2026-10-13)

총비용 $1.16 중 설계 호출 6회가 $1.03(89%), 호출당 입력 44K–55K 토큰, 캐시 적중 0. 입력의 약 60%가 무작위 1분봉 3구간 원시 CSV, 약 22%가 원문 전문이었다. 후보 6개는 첫 후보 하나를 다섯 번 고친 것이고(손절 0.55% 고정) 모두 비용 후 수익 미달로 탈락했다. 왕복 비용 약 0.31%가 평균 1분 범위 0.053%의 약 6배인데 설계 모델은 이 비용 장벽을 수치로 받지 못했고, 모든 조건에 웹 출처를 강제당해 데이터로 자기 가설을 확인할 수단이 없었다. 그래서 가장 어려운 일(비용 후에도 남는 우위가 데이터 어디에 있는가)을 Opus에게 측정 도구와 함께 맡기고, 웹 출처는 필수 근거에서 선택적 영감으로 내렸다.

CT의 단계별 실제 수행은 다음과 같다.

| 단계 | 실제 수행과 권한 |
| --- | --- |
| 계약/데이터 | 서버가 시장·종목·시간순 경계·비용·자본·위험·후보/시간/비용 한도를 저장한다. Massive 과거 분봉/Upbit 공개 페이지를 수집·캐시·재개하고 품질을 측정한다. |
| 조사(선택) | OpenAI의 실제 `web_search`를 호출한다. 제공자 검색 증거에 나온 URL만 읽으며, 본문·제목·확인 시각·해시를 저장한다. 검색이 실패하거나 증거 있는 URL·읽을 수 있는 원문이 0개면 연구를 멈추지 않고 출처 없이 설계로 넘어가며 `ct.sourceNote`로 화면에 표시한다. |
| 접근법 | 읽은 원문에 실제 존재하는 인용만 허용한다. 원리, 가격/거래량 구조, 시장 국면, 구현 가정과 재량 요소를 구분한다. 확인되지 않은 발표일은 null로 강제한다. |
| 설계 세션 | Opus 5.5 도구 루프(아래 「설계 세션」). 비용 장벽 표를 먼저 받고 `query_conditional_returns`·`read_bars`·`screen_rule`로 학습 구간에서 가설을 검증한 뒤 `submit_candidates`로 후보 0–3개를 제출한다. 무작위 원시 CSV와 원문 전문은 더 이상 넣지 않는다. |
| 실험/수정 | 제출 후보를 정규화 해시로 중복 제거하고 순서대로 학습 구간 `replayCT`+`ctGate`로 거른다(무료). 학습 게이트를 넘은 후보만 개발, 비용 2배, 진입 1봉 지연, 손절 ±10%를 실행한다. 통과 후보가 여럿이면 개발 일평균이 가장 높은 것을 동결한다. 모두 탈락하면 새 `reflect` 세션을 연다(이전 대화를 잇지 않고 측정 기록 블록에 결과를 덧붙여 시작). |
| 위험 검토 | 규칙 해시를 동결하고 다른 회사 검토자가 근거 대응·누출·체결·과최적화를 검토한다. 설계 세션의 전체 조회 목록(조건·요약 결과), 제출·기각 가설, 학습 게이트 탈락 후보, 근거 매핑을 함께 받아 데이터 스누핑과 다중 검정 가능성을 판단한다. 인용된 원문만 본문과 함께 전달한다. 제공자 장애는 보류이며 승인으로 대체하지 않는다. |
| 최종 평가 | 최종 기간 노출을 먼저 영구 기록한 뒤 동결 규칙으로 평가한다. 최종 성과는 설계 모델에 전달하지 않는다. 최종 평가 이후 수정/재도전하지 않는다. |
| 증거 검토/패키지 | 독립 최종 검토와 서버 수치 게이트를 모두 통과해야 패키지 생성/등록한다. 원문, 가설, 규칙, 버전/해시, 실험, 제한, 차트 근거를 함께 보존한다. |

`lib/ct-tools.ts`가 입력/출력 스키마와 단계 권한을 검사한다. 도구는 데이터 현황, 수집, 허용 기억, 검색, 읽기, 비용 장벽, 조건부 수익 조회, 1분봉 열람, 학습 사전 검사, 후보 제출, 컴파일, 백테스트, 실패 진단을 제공한다. 검토 모델 호출도 기존 완료 응답/사용량 장부에 기록된다. 시장/종목/기간/예산은 모델 입력으로 변경할 수 없다. 실주문 도구는 없다. 성과 필드를 넣은 설계나 임의 코드/eval은 거부한다.

검색·읽기는 제품 안에서 수행한다. Node에서는 DNS의 모든 주소를 검사하고 검증 주소에 HTTPS 연결을 고정한다. 사설/메타데이터 주소, 사용자정보 포함 URL, 타 호스트 리다이렉트, 과대 본문을 거부한다. PDF·영상 내용 추출·로그인 자료는 지원하지 않는다. YouTube HTML을 읽었다는 사실이 영상 강의를 확인했다는 뜻은 아니다. 독립 검토는 내용 의미의 일치도 판단하며, 코드의 대응 검사는 검토를 대체하지 않는다.

## 설계 세션 (2026-10-13)

`design`/`reflect` 단계는 `generationCall` 1회가 아니라 **설계 세션**이다. 한 번의 진행(advance)마다 모델 턴 하나 또는 그 턴의 도구 실행 묶음 하나를 처리하고 저장한다.

**세션 시작 컨텍스트**(도구 호출 없이, 안정적인 것부터): 시스템 지시(역할·목적 함수·DSL·과최적화 규칙, `CT_DESIGNER_SYSTEM`) → 고정 블록(계약·비용·게이트·한도, 비용 장벽 표, `ctAnalyst` 원리 요약과 출처 id·제목·URL, 허용 기억의 규칙 텍스트) → 이전 세션 기록(조회 목록, 기각 가설, 후보별 규칙 텍스트와 학습·개발·스트레스 핵심 수치·탈락 사유; 전체 spec JSON은 부모로 지정 가능한 개발 실험 후보만; 세션 사이에 뒤에만 추가) → 이번 세션 안내와 사용자 brief. 원문 전문과 원시 가격 CSV는 넣지 않는다.

**비용 장벽 표 `cost_hurdle`**: 학습 구간 5봉마다 다음 봉 시가 진입을 가정해 보유 5/15/60/240/390봉의 MFE/MAE 분위수(p10–p90)와 MFE가 왕복 비용의 1·2·3배를 넘는 비율을 계산한다. 시간대(코인 UTC 4구간, 주식 개장 60분·장 중반·마감 60분)와 직전 60봉 범위 3분위 변동성 국면으로 나눈 표와 한 줄 결론을 붙인다. 왕복 비용은 `replayCT`와 같은 `ctNetTradePct` 공식이다(BTCUSDT 계약 0.3095%, 비용 2배 0.618%).

**도구**(모두 학습 구간 전용·서버 계산·무료, `tool()`을 거쳐 `ct_tools`에 캐시되어 재개 시 재계산하지 않음):

| 도구 | 내용 |
| --- | --- |
| `query_conditional_returns` | DSL 조건 그대로의 1–4단계 시퀀스로 이벤트를 찾는다(`detectCT`를 `replayCT`와 같은 이력 창·feature 캐시로 호출). 보유 시간별(최대 5개) 총수익 분위수, 비용 후 평균·중앙값·비용 2배, MFE/MAE, 같은 시간대 구성의 무조건 기준선 대비 차이, 손절·목표 격자(최대 4×4, `ctExit` 그대로) 목표 먼저/손절 먼저/시간 청산 비율과 비용 후 기대값, 월별 이벤트·기대값, `read_bars` 기준 시각. 앞을 내다보는 구간이 `trainingToMs`를 넘는 이벤트는 버린다. 결과의 `queryId`가 근거 id다. |
| `read_bars` | 서버가 제공한 시각(조회 대표 이벤트, 부모 후보·사전 검사의 학습 거래 시각)만 최대 4개, 앞뒤 합계 240봉. 첫 시가 대비 bp 정수 o/h/l/c, 구간 중앙값 대비 거래량 배수, 시각은 첫 줄과 30봉마다. |
| `screen_rule` | 완성 spec을 `validateCTSpec` 후 학습 구간만 `replayCT`로 돌려 `ctSummary`와 `ctGate` 사유를 돌려준다. 개발 결과는 돌려주지 않는다. 이 리플레이는 실험 단계의 학습 백테스트와 같은 캐시를 쓴다. |
| `submit_candidates` | 후보 0–3개와 `noEdgeReason`, `rejectedHypotheses`. 서버가 zod·명세·근거를 다시 검증하고 실패하면 `is_error` tool_result로 같은 세션에서 고치게 한다. 후보 0개는 「통과 전략 없음」 정상 종료(최종 구간 미개봉). `strict: true`는 실제 API가 400 "compiled grammar is too large"로 거부해(2026-10-13 측정, 비용 $0) 쓰지 않는다. 어떤 도구도 strict가 아니며 서버 zod 검증이 그 역할을 한다. |

**한도**(`CT_POLICY`, 이전 계약에 없으면 현재 값): 세션당 모델 턴 12회, 도구 호출 24회, `screen_rule` 6회, 연구당 세션 3회. 계산 시간은 기존 `maxComputeMs`(600초)를 공유한다. 마지막 턴 직전(턴·도구 한도 또는 예산 여유가 턴 예약의 2배 미만)에 "지금 제출하라"는 안내를 tool_result 뒤에 붙인다. `tool_choice`는 강제하지 않는다(`auto`). 그래도 제출하지 않으면 세션을 실패로 기록하고, 실패 2회 또는 세션 한도면 「통과 전략 없음」으로 끝낸다. 후보 한도 6은 **제출된(중복 제거 후) 후보 수**로 센다. 정체·중복 한도 규칙은 유지한다. 활성 작업 한도는 짧은 Opus 턴이 많아져 1,800초에서 3,600초로 늘렸다(새 계약부터).

**근거 규칙(근거 버전 2)**: `spec.sourceIds`·`mapping[].sourceId`는 근거 id다 — 확인된 웹 출처 id, 또는 이 실행에서 완료된 학습 구간 `query_conditional_returns`의 `queryId`. 조회 근거는 그 조회가 같은 feature와 같은 `timeframe`을 실제로 측정했을 때만 인정한다(lookback·임계값 차이는 `implementationAssumption`에 적는다). 존재하지 않는 id, 다른 실행의 id, 학습 구간 밖 조회는 거부한다. 수락된 후보에 `evidenceVersion: 2`가 붙고, 필드가 없는 옛 후보와 등록 패키지는 웹 출처 규칙으로 계속 읽힌다. 부모가 있으면 실측 문제·변경·기대 효과가 필요하고, 새 메커니즘은 `parentId: null`로 낸다.

**요청 형태(Opus 5.5)**: `thinking: {type: "adaptive"}`, `output_config.effort: "high"`(기본 medium이므로 명시), `tool_choice: auto`, temperature·budget_tokens 없음, 스트리밍 후 `finalMessage()`. 캐시 지점은 시스템 프롬프트(앞에 렌더링되는 도구 정의 포함), 첫 메시지의 고정 블록 끝, 최상위 자동 캐시(최신 블록) 3개다. assistant `content`(thinking 블록·서명 포함)는 수정 없이 다음 요청에 그대로 붙인다. `refusal`·`max_tokens`는 기존 `IncompleteResponseError` 경로이고, 절단은 한도 64,000토큰·effort medium으로 1회 재시도한다.

**내구성·비용 장부**: 세션의 모델 턴 하나하나가 `ask()`와 같은 `paidCall` 장부를 거친다 — 호출 전 턴 단위 예약(입력은 캐시 쓰기 단가, 출력은 턴 한도), `job.calls` 기록, 실시간 미터, 완료 응답 재사용 키(실행 id·세션·턴·직전 메시지 해시), 중단 시 미확인 비용, 절단 재시도. 메시지 기록은 `ct_session_messages(run_id, session, seq)`에 한 행씩 append-only로 저장하고(`strategy_generation_runs.payload`에는 참조만), 러너가 죽어도 저장된 턴부터 이어 이미 지불한 턴을 다시 사지 않는다. 취소 후 늦게 온 응답은 저장되지 않는다. 검토 예비 예산(`reserveFraction` 35%)은 유지하며, 새 세션은 턴 예약 3배 이상의 여유가 있을 때만 연다.

## 실행 명세와 동일 코드 계약

`ct-pattern-1`의 JSON DSL만 실행한다. 한 패턴은 시간순 1–4개 단계, 단계마다 AND 조건 1–6개와 단계 간 최대 봉 수로 구성된다. feature는 수익률, SMA 거리, 가격 범위, 상대 거래량, 변동성 수축 비율, 이전 고점/저점 거리, 범위 내 위치, 확정 스윙 고점/저점 거리다. lookback/offset은 과거의 2–120/0–120봉, 시간배수는 1/3/12다(1분 기준 1/3/12분 완성 봉). 최대 보유는 390봉(1분봉 기준 정규장 한 세션)이다. 2026-10-13 이전 엔진은 상위 봉 묶음의 연속성을 상위 봉 크기로 비교해 시간배수 3/12 조건이 항상 null이었다. 수정 후에야 실제로 평가된다. 스윙은 오른쪽 2봉 이후에만 확정한다. 상위 봉은 완성된 봉만 사용한다.

진입 유효기간, 최대 스프레드/괴리, 손절/목표/시간 청산, 마지막 단계 저점 무효화, 위험/배분/거래량 참여 한도, 쿨다운을 수치로 고정한다. 롱 현물/주식만 지원한다. 추세선 작도, 자유 코드, 임의 지표, 숏/레버리지, 재량 판단은 지원하지 않는다. 표현할 수 없는 조건은 설명에만 넣어 통과시킬 수 없다.

`lib/ct-engine.ts`의 `detectCT`, `ctExit`, `ctQuantity`를 백테스트와 모의/실전이 공유한다. 실시간 판단 경로에는 모델/연구 실행기 호출이 없다. 거래마다 시작 당시 spec/hash와 실제 신호 관측값을 저장한다. 이름·설명만 다른 동일 규칙은 정규화 해시로 탐지한다. 실제 실행 전에도 승인 해시를 확인한다.

## 검증과 시장 차이

기본 데이터는 최근 180일, 시간순 60% 학습 / 20% 개발 / 20% 최종이다. 각 경계에서 필요한 이력을 다시 확보하며 이전 구간 신호/포지션을 넘기지 않는다. 최소 500봉이 없거나 비정상/중복 가격이 있으면 보류한다. 동일 시장·겹치는 종목·겹치는 최종 기간을 다른 연구에서 다시 열지 않는다. 원문과 모델 사전학습이 과거 기간을 몰랐다고 주장하지 않는다.

백테스트는 완성 봉 이후 다음 봉 진입, 비용/스프레드/슬리피지, 거래량 참여, 최소 주문, 수량 정밀도, 신호 만료와 미체결을 반영한다. 같은 봉에서 손절/목표가 모두 닿으면 손절을 먼저 적용하고 불리한 갭은 시가로 처리한다. 보유 중 봉이 누락되면 `data_error`이며 낙관적 청산을 만들어내지 않는다. 무거래, 데이터 오류, 실행 실패, 전략 기준 미달을 구분한다. OHLCV 참여율 제한은 실제 과거 호가/대기열/부분체결 복원이 아니다. 모의는 현재 호가에서 전량 체결하는 단순 모델이고 실전은 실제 누적 부분체결을 대사한다. 이 차이는 검토와 전향 모의 요구에 포함된다.

서버 게이트는 거래 20건 이상, 비용 후 양수 수익, **일평균 비용 후 순수익 > 0**, 최대 낙폭 15% 이내, 규칙 준수 100%, 종목/월 집중도 제한이다. 일평균은 평가 구간의 모든 날(주식은 뉴욕 기준 거래일, 코인은 UTC 날짜)의 일별 순수익률 평균이며 무거래일은 0으로 넣는다. 수수료·세금·스프레드·슬리피지를 모두 뺀 값이다. 비용 2배·1봉 지연·손절 민감도도 총수익과 일평균이 모두 양수여야 통과한다. 이 필드가 없던 과거 결과는 저장된 일별 행에서 다시 계산한다. 목표 수익은 게이트와 별개다. $8/$16/$24 예산 안에서 유료 호출 전에 예약하며 웹 검색 요금은 중앙 모델 비용 설정을 사용한다. 후보 최대 6개(제출 기준), 설계 세션 최대 3회, 개발 실험 묶음 최대 12개, 누적 계산 600초(1분봉 BTC 180일은 약 26만 봉), 활성 작업 3,600초(이전 계약 1,800초), 개선 정체 3회에서 정상 종료한다. 리뷰 예산을 미리 남긴다.

주식 연구는 Toss 인증·계좌·주문 API를 호출하지 않는다. 기존 MASSIVE_API_KEY로 7일씩 과거 분봉을 수집하며 빈 주간도 건너뛰어 계속한다. 수집 중이던 기존 Toss 연구는 재개 시 수집 데이터를 초기화해 공급자 혼합을 막는다. 이미 수집을 완료한 연구의 동결 데이터는 유지한다.

주식은 현재 종목 선택의 생존/선택 편향을 표시한다. 과거 구성 종목 복원이나 수정주가 복원이 아니다. 연구 원봉은 Massive adjusted=false이며 연속 세션 안에서만 패턴 이력을 사용한다. 집계는 UTC 격자이므로 60분 주식 봉은 정규장 첫 30분을 완성 60분 봉으로 만들지 않는다. 알려진 NYSE 2025–2028 휴장/조기 폐장만 버전 관리하며 그 밖의 연도는 거부한다. 긴급 폐장/거래정지/기업행사와 실전 IP 제약은 별도 한계다.

차트는 엔진의 패턴 구간, 조건값, 실제 사용 기준선, 확정 스윙, 신호/진입/손절/목표/청산과 거래량을 표시한다. 리플레이에서는 알려진 시점 이후만 선/표식을 보여준다. 수익·손실 대표 사례를 함께 선택하고 모든 연구 거래는 도구 결과 다운로드에서 확인한다. 운용 대시보드의 보유/거래 기록에서 개별 거래 차트를 열 수 있다. `ct_trade_charts`는 당시 관측한 봉과 실제 신호·체결·동결 해시를 별도 보존하므로 최신 시세 캐시가 사라져도 근거가 남는다. 최대 480봉(긴 운용은 처음 200/마지막 280봉)을 저장하며, 수정된 과거 봉은 원본을 덮어쓰지 않고 오류로 기록한다. 차트 저장 장애는 주문 감시/청산을 막지 않고 이벤트로 남긴다. 의도/근거 저장 중 만료된 매수 신호는 전송 직전에 다시 차단한다. 20봉 참고 고점/저점은 전략이 사용한 돌파선이라고 표시하지 않는다.

## 저장, 재개와 운용 안전성

기존 `strategy_generation_runs`에 CT 상태를 저장한다. `ct_data_pages`는 페이지 체크포인트, `ct_tools`는 완료 도구 응답, `ct_session_messages`는 설계 세션 메시지(append-only), `ct_replay_pages`는 전체 거래 기록, `ct_exposure`는 최종 기간 소진, `ct_strategies`는 등록 패키지, `ct_runtime`은 연구 러너 heartbeat, `ct_trade_charts`는 실제 운용 거래의 관측 봉과 규칙/체결 근거다. 큰 거래 목록은 별도 페이지에 저장하고 상태에는 대표 사례와 실제 총 거래 수를 남긴다.

브라우저/러너는 기존 DB lease로 같은 작업을 중복 실행하지 않는다. 완료 유료 응답과 도구 응답은 단계 저장 실패 후에도 재사용한다. 취소 후 늦게 온 응답은 상태/등록을 변경하지 못한다. 연구 기억은 동일 소유자·시장·주기·종목·비용·자본·엔진으로 제한하고 이전 개발 구간 결과만 전달한다.

장부는 `relay`, `surge`, `ct-stock`, `ct-crypto` × paper/live로 분리한다. 실계좌는 장부별 가상 잔액으로 격리됐다고 가정하지 않는다. 브로커 단위 DB 잠금, 실제 주문 가능 잔고/미체결, 소유 수량을 함께 검사한다. 다른 장부 미체결 매수의 잔여 수량 × 지정가 × 1.01 예약액을 추가 차감한다. 브로커가 이미 차감했다면 보수적으로 이중 예약되어 진입 가능 금액이 줄어들 수 있다. 주문 의도/identifier를 먼저 저장하고 응답 유실은 조회/대사한다. Upbit는 identifier로 복구하며 Toss가 client ID를 조회에 제공하지 못하는 경우 자동 재주문하지 않고 대기한다. 미확정 주문은 신규 진입과 정지 완료를 차단한다. 신호 만료, 오래된 호가, 손실 한도, 단일 포지션, 다른 장부 미확정 주문도 신규 진입을 차단한다.

브라우저를 닫은 뒤에는 상시 머신의 러너가 필요하다. 메모리 타이머는 영구 실행기로 쓰지 않는다. 연구 loop와 주문 감시 loop는 분리되어 있다. 연구 러너가 없으면 화면에 대기를 표시한다.

```sh
# .dev.vars는 서버 비밀이며 Git에 포함하지 않는다.
node --env-file=.dev.vars scripts/trading-runner.mjs --url http://localhost:3000
# 연구만 검증: 주문 감시 tick을 보내지 않는다.
node --env-file=.dev.vars scripts/trading-runner.mjs --generation-only
```

원격 실행에는 서버와 러너에 같은 `STRATEGY_RUNNER_SECRET`을 설정한다. Sites 원격 실행에서는 기존 사이트의 접근 정책에 맞는 인증을 확인한다. 요청이 실제 주문을 보내는 위치는 러너 머신이 아니라 대상 앱 서버이므로 Toss/Upbit의 허용 IP도 앱 서버 출구 IP여야 한다. 러너가 꺼지면 자동 매매 감시가 지속된다고 표시하지 않는다.

## 실제 검증과 아직 확인되지 않은 범위

2026-10-11/12 로컬 UI의 전략 생성 버튼으로 실제 연구 `705489fc-030b-467c-8a2c-ecd40b7b8d7c`를 실행했다. Upbit BTC/ETH 각 4,317개 완성 60분 봉, 44페이지와 실제 공개 검색/원문 읽기, 완료 모델 호출 7회, 후보 5개, 실제 리플레이 30회를 사용했다. 비용은 $0.5062536/$8이었다. 개선 정체에 따라 **통과 전략 없음**으로 정상 종료했고 최종 기간은 열지 않았다. 임의 성과나 임의 등록은 없었다. 요약은 [검증 기록](ct-evaluation-2026-10-12.json)에 있다. 이 기록은 실행 도중 저장된 엔진 산출물이며 이후의 비용 보고/차트 표시 개선을 적용해 과거 결과를 재작성하지 않았다.

실제 Upbit 현재가/호가/계좌 읽기와 Toss SPY 15분 연구의 원봉 4페이지 수집도 확인했다. 실제 주문은 0회다. 전체 주식 연구, 실제 통과 후보의 독립 검토/최종 평가/등록, 전향 모의 체결, 실전 주문은 실데이터 통합 검증되지 않았다. 통과→독립 검토→최종 동결→등록→동일 규칙 실행, 유실 응답/부분체결/취소 순서는 고정 모델 응답과 합성 데이터 테스트로 구분해 검증한다. 한 연구의 성과를 일반 수익성의 증거로 사용하지 않는다.

기본 연구 실행은 로컬 Node + SQLite + Parquet다. 웹사이트 변경의 호스팅 배포 대상은 Sites이며, [배포 문서](deployment.md)에 따라 기존 프로젝트의 빌드·D1 연결·API 동작을 검증한다. 로컬 연구 DB와 시장 파일은 Sites에 자동 이전되지 않는다. 과거 Vercel용 Node/Nitro 및 D1 REST 어댑터 구성은 기본 배포 완료 기준이 아니다.
