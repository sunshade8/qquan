## 1. 왜 하는가 (실측 근거)

CT 연구는 지금까지 모든 실행에서 「통과 전략 없음」으로 끝났다. 원인은 설계 모델의 지능보다 판 자체에 있다.

- **비용 장벽.** 코인 계약 비용은 수수료 0.1% + 스프레드 0.05% + 슬리피지 0.03%로, 왕복 약 0.31%다. 스트레스(비용 2배)에서는 0.62%다. BTC 1분봉 평균 범위는 0.053%다. 그런데 스프레드·슬리피지는 주식과 같은 값을 그대로 쓴다. BTCUSDT의 틱은 0.01 USDT로, 가격 대비 사실상 0에 가깝다. $1,000 규모 주문의 슬리피지도 측정된 적이 없다. 비용이 과대 추정됐을 가능성이 크다.
- **보유 시간.** 최대 보유 390봉(6.5시간)은 주식 정규장 길이를 코인에도 그대로 쓴 값이다. 코인은 24시간 시장이다.
- **관찰 창.** 조건이 볼 수 있는 과거는 최대 120봉 × 12분 = 24시간이다. 주식은 세션마다 이력을 리셋하므로 전일 차트를 아예 못 본다. 실제 단타 트레이더는 일봉·1시간봉으로 전일 고가·저가와 추세를 먼저 보고, 1분봉으로 진입 시점만 잡는다.
- **데이터 범위.** 기본 180일을 60/20/20으로 나누면 개발 구간은 36일이다. 비용을 넘는 셋업은 드물다. 예를 들어 하루 0.4건이면 개발 구간 거래는 약 14건이라 최소 20건 게이트에 구조적으로 걸린다. 로컬에는 BTCUSDT 1분봉이 2021-10부터 5년치, NVDA가 2024-10부터 약 2년치 있다.
- 실행 `893af88c`에서 설계자가 내린 결론: 하루 1회 이상 나오는 신호는 기준선 대비 +0.05–0.19%p로, 0.31%를 넘지 못한다.

**소유자 결정(바꾸지 말 것):**
- CT는 **단타(데이) 트레이딩**이다. 포지션은 하루를 넘기지 않는다. 며칠 보유는 범위 밖이다.
- **코인의 "하루" 경계는 UTC 00:00(KST 09:00)이다.** 이 시각에 보유 포지션을 강제 청산한다. 이유는 두 가지다.
  - 게이트의 코인 일별 집계가 이미 UTC 날짜 기준이므로, 하루 손익이 그날 안에서 닫힌다.
  - Binance와 Upbit의 일봉 경계도 이 시각이다.
- 주식은 기존대로 정규장 당일 청산이다.
- 데이터 해상도와 백테스트는 1분봉 고정이다. 바꾸는 것은 "몇 분봉 차트까지 볼 수 있는가"(관찰 창)이지, 백테스트 해상도가 아니다.

## 2. 작업 내용 (이 순서대로, 단계마다 측정하고 다음으로)

### 2.1 천장 측정 스크립트 (가장 먼저, 모델 비용 0)

에이전트를 바꾸기 전에 "이 판에 비용 후 우위가 존재할 수 있는가"의 상한을 서버 계산만으로 잰다. 이 결과가 2·3번 작업을 할지 말지를 정한다.

`scripts/research/ct-ceiling.ts`(기존 `scripts/research/*.ts`와 같은 실행 방식)를 만든다. 데이터는 로컬 Parquet를 `lib/ct-*`와 같은 로더로 읽는다.

1. **거래할 가치가 있던 순간(라벨).** 1분봉 매 시점 t에 대해 t+1 시가에 진입한다고 가정하고 라벨을 붙인다.
   - 양성 조건: 보유 상한 H 안에서 MFE가 `k × 왕복비용`에 먼저 닿고, MAE가 `−m × 왕복비용`에 닿지 않았다.
   - 기본값: k=3, m=1. H는 아래 보유 상한이며, 당일 경계를 넘지 않는다.
   - 같은 봉에서 둘 다 닿으면 손절 먼저로 본다(엔진 규칙과 같음).
2. **조합 격자.**
   - 비용: 현재 계약 비용 / 2.2절 실측 비용 / 각각의 2배.
   - 보유 상한: 60·240·390봉 / 당일 청산(코인은 UTC 00:00까지, 주식은 세션 종료까지).
   - 데이터: 180일 / 1년 / 3년(코인), 180일 / 전체(NVDA).
3. **예측 가능성 상한.**
   - 각 조합에서 기저율(양성 비율, 하루 평균 양성 수)을 잰다.
   - 단순 피처 세트로 얕은 결정 트리(깊이 ≤ 3, 잎 최소 표본 = 기간 일수 이상)를 학습한다. 피처는 현재 DSL 10개에 시간대와 1시간·일봉 수준의 같은 피처를 더한 것이다.
   - **시간순 워크포워드**(학습 → 바로 다음 구간 검증, 최소 4폴드)로 검증한다.
   - 검증 지표: 선택된 잎에 진입했을 때 정해진 손절·목표·당일 청산 규칙의 **비용 후 거래당 기대값**과 **일평균 순수익**. 비용 1배·2배 각각 잰다.
4. **산출물.** `docs/research/ct-ceiling-<날짜>.md`에 조합별 표와 한 문단 결론을 쓴다.
   - 결론은 "어느 조합에서 비용 2배 워크포워드 일평균이 양수인 잎이 존재하는가"다.
   - 반복 검정 수를 함께 기록한다(조합 × 피처 × 분할).
   - 결과가 전부 음수여도 그대로 보고한다. 숫자를 좋게 만들려고 조합을 늘리지 마라.

이 스크립트의 라벨 함수와 워크포워드 함수는 3번 작업의 `contrast_moves` 도구가 재사용한다. 그러니 `lib/ct-moves.ts` 같은 순수 함수 모듈로 분리하고, 스크립트는 그것을 호출만 하게 하라.

### 2.2 비용을 실측 기반 프로필로

1. **거래소별 비용 프로필**(`lib/ct-costs.ts` 등)을 만든다. 각 프로필은 다음을 가진다.
   - 수수료(편도, 매수·매도), 세금, 스프레드, 슬리피지.
   - 출처(공식 수수료 문서 URL과 확인일, 측정 스크립트와 측정 기간).
   - 버전.
2. **수수료**는 공식 문서에서 확인한 값만 쓴다.
   - Binance Spot 기본 등급 수수료와 Upbit KRW 마켓 수수료를 공식 문서로 확인해 프로필에 적는다.
   - 기억에 의존하지 말고 확인 시각과 URL을 남긴다.
   - 주식은 기존 `lib/broker-costs.ts`(Toss)를 그대로 쓴다.
3. **스프레드·슬리피지는 측정한다.**
   - 인증 없는 공개 호가 API(Binance `bookTicker`/`depth`, Upbit `orderbook`)로 최소 72시간 스냅샷을 수집한다. 1분 간격이면 충분하다.
   - 계약 자본 규모($1,000, 그리고 10배)의 시장가 매수·매도가 호가를 몇 bp 밀어내는지 계산한다.
   - 결과는 SQLite에 저장하고, 측정 스크립트는 `scripts/data/`에 둔다.
   - 프로필 값은 측정 분포의 **p90**(보수적)으로 정하고, 측정값 아래로는 절대 내리지 않는다.
4. **새 계약만 프로필을 쓴다.**
   - 계약에 `costProfile: {id, version}`을 저장한다.
   - 이전 계약과 등록 패키지는 저장된 `costs`를 그대로 쓴다.
5. **비용 2배 스트레스는 유지한다.** 실측 비용이 낮아져도 스트레스 테스트를 제거하거나 완화하지 마라.
6. 연구 거래소(Binance)와 실행 거래소(Upbit)가 다르다는 기존 차단 정책은 바꾸지 않는다. 프로필은 연구 데이터의 거래소를 따른다. 화면에 어떤 프로필로 연구했는지 표시한다.

### 2.3 단타 보유 규칙

1. **코인 당일 경계 강제 청산을 추가한다.**
   - UTC 00:00을 지나는 첫 봉에서 보유 포지션을 그 봉 시가로 청산한다. 청산 사유는 `day_end`다.
   - 경계 직전 봉의 종가로 청산하는 방식이 더 맞다면 주식의 `session` 청산과 같은 방식으로 통일하라. 어느 쪽이든 백테스트와 모의·실전이 같은 함수를 쓴다.
2. 코인의 `maxHoldBars` 상한을 1440으로 올린다(주식은 390 유지). 상한은 시장별로 검증한다.
3. 당일 경계 N분 전부터 신규 진입을 막는 `noEntryBeforeDayEndMinutes`(0–240)를 spec에 추가한다. 기본값 0. 주식에도 적용된다.
4. `ctExit`, `replayCT`, `ct-trading-engine.ts`(모의·실전)가 같은 규칙을 공유하는지 테스트로 고정한다.
5. `cost_hurdle` 보유 지평에 코인은 720·1440봉, 그리고 "당일 경계까지"를 추가한다. 당일 경계를 넘는 지평은 경계에서 잘라 계산한다.

### 2.4 관찰 창 확장 (상위 시간대)

1. `timeframe`에 60·240·1440(1시간·4시간·일봉)을 추가한다.
   - 모두 1분봉에서 **완성된 봉만** 집계한다.
   - 주식 일봉은 세션 단위(NY 정규장)로 만든다. 주식 60분봉의 기존 UTC 격자 한계가 있으면 이번에 세션 기준 격자로 고친다(옛 엔진 패키지 동작은 유지).
2. lookback 상한은 시간 배수와 함께 검증한다. 관찰 가능한 과거는 최대 30일이다(예: 일봉 lookback ≤ 30).
3. **주식의 세션 리셋을 상위 시간대 피처에서는 풀어 준다.**
   - 1·3·12분 조건은 기존대로 세션 안 연속 봉만 쓴다.
   - 60/240/1440 조건은 이전 세션의 완성 봉을 쓸 수 있다.
   - 분할·기업행사 경계 격리(NVDA 분할 처리)는 유지한다.
4. **성능.** 지금 `higherBars`는 조건 평가마다 다시 집계한다. 상위 시간대가 커지면 계산 예산(600초)을 넘을 수 있다.
   - 심볼·시간 배수별로 완성 상위봉을 한 번 만들고, 인덱스로 참조하는 캐시를 도입한다.
   - 코인 1분봉 1년 리플레이 처리 시간을 변경 전후로 측정해 보고한다.
5. 코인 피처 이력 상한(1,500봉)은 상위 시간대 조건에 필요한 만큼 늘린다. 1분 원봉을 전부 들고 다니지 말고 상위봉 캐시를 쓴다.
6. 새 timeframe을 쓰는 spec은 엔진 버전을 올린다(`ct-pattern-2` 등). `ct-pattern-1` 등록 패키지의 판정 결과가 비트 단위로 같게 유지되는지 회귀 테스트로 고정한다.

### 2.5 데이터 범위와 종목

1. 요청 `days` 상한을 코인 1,095일(3년), 주식은 로컬 coverage 범위로 올린다. 기본값은 2.1 천장 측정 결과를 보고 정하고, 그 근거를 `docs/ct.md`에 적는다.
2. 시간순 60/20/20 분할은 유지한다.
   - 개발 결과 요약에 **분기별 일평균 순수익과 양수 분기 비율**을 추가한다. 게이트는 바꾸지 않고, 설계자·검토자에게 보여 주는 안정성 정보로만 쓴다.
3. 계산 예산(`maxComputeMs`)과 활성 작업 한도는 측정한 처리량을 근거로 새 계약에서만 올린다. 옛 계약 호환 패턴(`CTPolicyLater`)을 따른다.
4. **코인 종목 추가.** 같은 Binance Public Data 파이프라인으로 ETHUSDT, SOLUSDT 1분봉을 받을 수 있게 하라(Settings 버튼, catalog, coverage, 품질 보고 동일).
   - 연구 요청에서 BTC/ETH/SOL 1–3개를 고를 수 있게 하라.
   - 기존 종목 집중도 게이트(80%)는 유지한다.
5. 최종 구간 재사용 금지(`ct_exposure`)는 그대로 지킨다. 데이터 범위가 길어져 이전 실행의 최종 구간과 겹치면, 시작 전에 화면에서 이유와 함께 거부한다.

## 3. 바꾸면 안 되는 것 (불변 조건)

- 새 연구는 1분봉 백테스트. 5/15/60분은 기존 등록 패키지 호환용으로만 남긴다.
- 시간순 학습 60% / 개발 20% / 최종 20%. 설계 도구는 학습 구간만 본다. 최종 구간은 동결·노출 기록 후 1회만 평가한다.
- 서버 수치 게이트(`ctGate`, `ctNetPositive`: 거래 20건 이상, 총수익·일평균 양수, 비용 2배·1봉 지연·손절 ±10% 스트레스)와 독립 검토 통과 없이는 등록 불가. 이번 작업에서 게이트를 완화하지 마라.
- 백테스트와 실전·모의는 같은 `detectCT`/`ctExit`/`ctQuantity`를 공유한다.
- 롱 전용. 포지션은 하루를 넘기지 않는다.
- 실주문 도구 없음, 임의 코드·eval 없음, 동시 실행 1개, lease·취소·재개, 비용 장부의 의미.
- 이전 계약·등록 패키지·실행 기록이 그대로 열리고 같은 결과를 낸다.

## 4. 테스트 (`node --experimental-strip-types --test tests/*.test.mjs` 전부 통과)

1. 라벨 함수: 합성 봉으로 MFE/MAE 선후, 같은 봉 동시 도달(손절 먼저), 당일 경계 절단.
2. 워크포워드 분할이 미래 데이터를 학습에 쓰지 않는다.
3. 비용 프로필: 새 계약은 프로필 값을 저장하고, 옛 계약은 저장된 `costs`를 쓴다. `cost_hurdle`의 왕복 비용과 `replayCT`의 실제 비용이 일치한다.
4. 코인 UTC 00:00 강제 청산: 경계를 넘는 포지션이 `day_end`로 닫히고, 백테스트와 모의 엔진의 결과가 같다. `noEntryBeforeDayEndMinutes` 동작.
5. 상위 시간대: 미완성 상위봉 미사용(미래 봉을 붙여도 과거 시점 피처값 불변), 주식 상위봉의 세션 경계 처리, 분할 경계 격리.
6. `ct-pattern-1` 회귀: 기존 spec의 신호·거래·게이트 결과 불변.
7. 기간 상한, 다중 코인 종목 계약 생성, 최종 구간 중복 거부.

## 5. 실제 실행 검증 (필수)

1. 2.1 천장 측정 스크립트를 실제 로컬 데이터로 끝까지 돌리고 `docs/research/ct-ceiling-<날짜>.md`를 만든다.
2. 비용 측정 스크립트를 최소 72시간 돌려 프로필을 확정한다. 72시간을 기다릴 수 없는 상황이면 확보된 시간만큼의 결과와 그 한계를 보고하고 프로필을 "잠정"으로 표시한다.
3. `npm run local`로 앱과 러너를 띄우고, 브라우저에서 CT → 코인 → 새 기본값으로 **전략 생성**을 실제로 끝까지 실행한다.
4. `~/.qquan/state/research.sqlite`에서 다음을 뽑아 보고한다.
   - 사용한 비용 프로필과 왕복 비용, 데이터 기간, 리플레이 처리 시간.
   - 후보 수 → 학습 통과 → 개발 통과, 탈락 사유 분포.
   - 실행 `893af88c`와 나란히 놓은 비교표.
5. 비밀값은 출력·커밋하지 않는다.
