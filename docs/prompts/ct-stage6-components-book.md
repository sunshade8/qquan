## 1. 왜 하는가 (실제 기록)

`~/.qquan/state/research.sqlite`의 `strategy_generation_runs`와 `ct_playbook`에서 읽기 전용으로 확인한 사실이다. 시작할 때 같은 쿼리로 다시 확인하고, 달라진 점이 있으면 기록하라.

### 1.1 연구가 5/11단계에서 끝난다

최근 완료된 CT 연구 **10개(`a682e11b` … `190f80a2`)가 모두** 다음 상태로 끝났다.

- 단계: 5/11 「가설·규칙 설계」(`design`)
- 종료 사유: `설계자 판단: 비용 후 우위 미발견 · 통과 전략 없음 · 최종 기간 미개봉`
- 설계 세션 1개, 실험된 후보 0개, `screen_rule` 0회, 모델 턴 5–7회(한도 16)
- 사용 비용 $0.43–$0.97, 예산 $8. **예산의 90% 가까이를 쓰지 않은 채 끝났다.**

원인은 코드 한 줄이다. `submit_candidates`가 후보 0개로 오면 `ct-research-store.ts` 약 1735행의 `else if (!submission.candidates.length) done(...)`이 연구를 바로 끝낸다. `maxSessions: 3`인데 2·3번째 세션(`reflect`)은 열리지 않는다. 6–11단계(실험·수정·위험 검토·최종·최종 검토)는 한 번도 실행되지 않았다.

### 1.2 약하지만 실제일 수 있는 우위가 들어갈 자리가 없다

연구 `190f80a2`(NVDA)의 `noEdgeReason`에 이렇게 적혀 있다: 가장 강한 조합(전일 종가 −1.95% 이하 + 당일 범위 하단 17.5%, 5분봉)이 82건/42일에서 총수익 평균 +0.06~+0.19%였고, 기준선보다 0.07~0.20%p 나았다. 하지만 왕복 비용 0.31%에 못 미쳐 기각했다.

지금 구조에서 우위는 **규칙 하나가 혼자 비용을 넘어야만** 살아남는다.
- 설계자 지시문: "do not submit a rule that already fails on training"
- 서버 `ctGate`: 후보 하나의 비용 후 순수익 > 0

그래서 기준선을 이기지만 비용은 못 넘는 신호는 전부 "기각"으로 플레이북에 쌓인다. 현재 `ct_playbook`에는 분봉 기준으로 `rejected_in_training` 120개, `development_failed` 12개가 있다(일봉 시드 제외). 이 중 일부는 **결합했을 때만** 비용을 넘을 수 있다. 하지만 지금 구조는 그런 우위를 원리적으로 발견할 수 없다.

### 1.3 이미 잰 것 (기대치를 정하는 기준)

천장 측정(64+140+192개 조합)은 깊이 3 이하의 트리로 했다. 깊이 3 트리는 **조건 최대 3개를 AND로 겹치는 결합**이므로, 컨플루언스 방식의 결합은 이미 시험됐고 표본 밖에서 후보가 없었다. **아직 시험하지 않은 것은 두 가지다.**
- **더하기형 결합**: 약한 신호 여러 개의 점수를 합산하는 방식. 얕은 트리는 이 구조를 잘 잡지 못한다.
- **북 단위 평가**: 여러 부품을 동시에 운용하면서 겹치는 포지션의 비용 상쇄를 반영하는 평가

이 작업은 이 두 가지를 연구 에이전트가 직접 다룰 수 있게 만드는 일이다. 천장 측정 결과는 "하지 말라"는 근거가 아니라 "무엇을 기대하면 안 되는지"의 기준이다.

### 1.4 소유자의 원칙 (포커 비유, 반드시 지시문에 반영)

- 수수료는 레이크다. **"확실할 때만 쳐라"가 아니라 "레이크를 내고도 +EV인 스팟은 친다"**가 원칙이다. 최적화 대상은 거래당 확실성이 아니라 총 EV, 즉 Σ(조건부 기대값 − 비용)이다.
- 혼자 레이크를 못 넘는 약한 신호는 "버리는 핸드"가 아니라 **"다른 신호와 겹칠 때 쓰는 카드"**다. 부품으로 등록한다.
- 목표 지표는 "매일 무조건 수익"이 아니다. **비용 후 일평균, 수익일 비율, 일간 샤프, 최대 낙폭**이다. 화면과 보고서에 이 넷을 함께 보여라.
- 범위는 **차트 모양 매매**다. 종목 선택, 다종목 확장, 뉴스, 타 자산 신호를 부품이나 개선안으로 넣지 마라. 부품은 계약에 있는 종목의 차트에서만 나온다.
- 봉 주기는 **에이전트가 부품마다 고른다**(free bars). 사용자 봉 주기 선택 옵션을 만들지 마라.

## 2. 개념 정의 (이 작업 전체의 계약)

| 용어 | 정의 | 판정 기준 |
|---|---|---|
| **부품(component)** | 기존 DSL 규칙 하나(진입 조건 + 보유 창). 단독 매매 전략이 아니라 **신호**다 | **비용 전** 총수익이 기준선(같은 시간대 구성의 무조건 진입)을 이기는가 |

부품 판정은 비용 전 기준이지만, **비용을 무시하는 단계는 어디에도 없다.** 비용은 북에서 정확히 한 번 계산하고, 통과 기준은 낮추지 않는다.

### 3.1 5/11단계 조기 종료 수정

새 정책에서 설계 세션 종료 후의 분기를 다음처럼 바꾼다.

| 제출 결과 | 지금 | 새 정책 |
|---|---|---|
| 후보 ≥ 1 | `experiment` | 같음 |
| 후보 0, 부품 ≥ 1 | — | `experiment`(부품 판정) → `book` |
| 후보 0, 부품 0, **첫 번째 연속** | 즉시 `done` | `reflect` 세션을 연다(아래 과제) |
| 후보 0, 부품 0, **두 번째 연속** | — | `done("두 세션 연속 후보·부품 없음 …")` |

- `reflect` 세션 과제: 이전 세션이 쓰지 않은 커버리지 칸(`ctCoverage`의 안 쓰인 칸), 아직 `dead`가 아닌 계열, 그리고 **"기준선은 이기지만 비용은 못 넘은 측정"을 부품으로 다시 보는 일**을 명시한다. 과제 문장에는 직전 세션의 `noEdgeReason`과 기각 가설 요약을 넣되 누출 규칙(숫자 가림)을 지킨다.
- 서버 확인: 후보 0·부품 0 세션 다음의 `reflect` 세션에서 다시 0/0을 제출하려면, 그 세션에서 **이 실행의 장부에 없던 새 가설 서명을 2개 이상** 측정했어야 한다. 아니면 제출을 오류로 돌려보낸다(세션 안에서 고칠 수 있게). 단, 마지막 턴 통지(`finalNotice`) 뒤와 예산 부족 시에는 받아들인다.
- 종료 사유에는 **어느 단계에서, 왜, 예산을 얼마 남기고** 끝났는지를 쓴다. 예: `5/12 설계 · 두 세션 연속 후보·부품 없음 · 예산 $6.80 남음`.
- 기존 시간·계산·예산·세션 한도 종료는 그대로 둔다. 예산 여유 검사(`headroom < turnReserve * 3`)도 그대로 둔다.

### 3.2 부품 제출과 서버 판정

- `submit_candidates`(새 정책 스키마)에 `components` 배열을 더한다. 항목마다 다음을 받는다.
  - `spec`: 기존 DSL, 진입과 보유 창
  - `hypothesis`, 근거 `mapping`: 기존과 같은 근거 인용 규칙
  - 봉 주기
  - `whyNotAlone`: 혼자 비용을 못 넘는 이유
- 부품은 최대 8개다. 단일 후보 1–3개와 함께 제출해도 된다.
- **학습 구간 부품 게이트**(서버가 계산한다. 기본값을 사전 등록하고, 결과를 본 뒤 바꾸지 마라):
  - 이벤트 ≥ 60, 고유 일수 ≥ 30
  - 비용 전 총수익 − 기준선 > 0. **일 단위 군집 부트스트랩** 단측 p ≤ 0.05(이벤트가 겹치므로 이벤트 단위 t검정을 쓰지 마라)
  - 양수인 월이 60% 이상, 상위 5일이 총이익의 40% 이하
- **개발 구간 확인**: 같은 부호이고 총수익 − 기준선 > 0, 이벤트 ≥ 20. 실패한 부품은 `component_dev_failed`로 기록하고 북에 넣지 않는다.
- **중복 제거**: 두 부품의 진입 이벤트가 70% 넘게 겹치면 p가 더 작은 쪽만 남긴다.
- 부품 하나는 장부에서 검정 1회로 센다(`ctTestSignature` 규칙 그대로). 부품이라고 장부를 피하게 하지 마라.

### 3.3 북 엔진 (`lib/ct-book.ts`, 엔진 `ct-book-1`)

- **같은 함수가 연구·모의·실전에서 돈다**(「실행 명세와 동일 코드 계약」). 순수 함수 `ctBookStep(state, bar, components, rule)` 형태로 만들고, 기존 `ct-engine.ts`의 봉 순회·비용 모델·1봉 지연·당일 청산·주식 세션 처리를 재사용하라. 따로 복제하지 마라.
- **점수**: 각 부품은 신호 발생 후 자기 보유 창 동안 활성(+1)이다. 북 점수 = 활성 부품 수.
- **결합 규칙**은 사전 정의된 두 가지만 허용한다(학습 가중치 금지).
  - `vote`: 점수 ≥ k일 때 롱. k ∈ {1, 2, ⌈n/2⌉} 중 **학습 구간에서만** 고른다.
  - `confluence`: 지정한 부품 2개가 동시에 활성일 때만 롱.
- **포지션**은 종목당 순포지션 하나다. 겹치는 부품 신호는 포지션을 늘리지 않으므로 **비용을 이중으로 내지 않는다**(상쇄). 비용은 실제 진입·청산에만 부과한다.
- **청산**: 점수가 k 밑으로 내려가면 청산한다. 북 수준 손절(ATR 또는 %), 최대 보유, 당일 경계 청산은 계약을 따른다. 청산 구조 선택도 학습 구간에서만 한다.
- **방향**: 현재 CT 계약은 롱 전용이다. 숏은 §3.8의 capability가 실제로 있을 때만 켠다.
- **판정**: 북 결과에 기존 `ctGate`를 **그대로** 적용한다(최소 거래 20, 비용 후 순수익 > 0, 일평균 > 0, 낙폭 15%, 준수 100%, 시기 집중). 비용 2배 스트레스와 1봉 지연 스트레스도 적용한다. 개발 구간은 통과·탈락 판정에만 쓴다.
- **보고 항목**: 부품별 기여도(빼기 하나 분석, 개발 구간), 비용이 총이익에서 차지하는 비율, 수익일 비율, 일간 샤프, 최대 낙폭. 부품 하나가 순이익의 70% 넘게 차지하면 "사실상 단일 전략"으로 표시한다(게이트는 아님).
- (북 구성, 결합 규칙, k, 청산 구조)는 장부에서 하나의 가설 서명이다. 북 후보는 연구당 최대 3개다.
- 통과한 북은 기존 흐름(`risk_review` → `final` 1회 → `evidence_review`)으로 간다. **최종 구간은 동결된 북 하나에 대해 한 번만 연다.**

### 3.4 단계 표시

- 새 정책 계약의 단계 목록에 `book`(「부품 결합·북 실험」)을 `reflect` 다음에 넣는다(총 12단계). 이전 계약의 진행 화면은 11단계 그대로 보여야 한다. 단계 목록을 계약 버전에서 얻도록 바꿔라.
- `book` 단계 힌트: "통과한 부품을 사전 정의 규칙으로 결합해 비용 후 성과를 실험합니다".

### 3.5 설계자 지시문 (새 정책 `CT_DESIGNER_SYSTEM_BOOK`)

6의 지시문에서 다음만 바꾸거나 더한다. 나머지 바이트는 유지하고, 차이를 `docs/ct.md`에 적는다.

- §1.4의 원칙을 영어 지시문으로 옮긴다. 요지는 다음과 같다. A measurement that beats its time-of-day baseline before costs but not the round-trip cost is a component, not a rejection; register it with `whyNotAlone`. Costs are charged once, on the book's actual position changes. Do not stop because no single rule clears the cost. Stop only when neither a candidate nor a component survives, and say which coverage cells you tried.
- `noEdgeReason`에는 부품 후보를 찾았는지와 왜 부품 게이트를 못 넘을 것으로 봤는지를 반드시 적게 한다.
- 다중검정 경고는 그대로 둔다. 부품도 검정으로 센다는 사실을 지시문에 명시하라(경고를 없애서 우연을 늘리는 방향으로 고치지 마라).

### 3.6 기억과 검토자

- 플레이북 등급에 `component_passed`, `component_dev_failed`, `book_development_failed`, `book_passed_final`, `book_failed_final`을 더한다.
- 계열·교훈·커버리지(`ct-families`, `ct-lessons`)가 새 등급을 읽게 한다. `dead` 판정 규칙에서는 **`component_passed`인 계열을 `dead`로 만들지 않는다.**
- 다른 실행에서 통과한 부품은 구조(피처·봉·방향)만 근거로 재사용할 수 있다. 수치는 기존 누출 규칙을 따르며, 이번 실행의 학습 구간에서 **다시 측정**해야 하고 장부에 센다.
- 위험·증거 검토자 입력에 다음을 더한다: 북 구성, 부품 간 이벤트 겹침 행렬, 빼기 하나 기여도, 비용 비중, 누적 검정 수. 지시에 "이 북은 우연히 좋아 보이는 부품들의 조합인가, 하나의 부품이 전부인가"를 넣는다.

### 3.7 화면 (기존 `ui-*` 프리미티브와 CT 스타일만 사용)

- 연구 상세에 「부품」 표: 봉, 조건 요약, 이벤트/일수, 총수익 − 기준선(비용 배수로도), p, 양수 월 비율, 학습·개발 판정, 중복 제거 여부
- 「북」 카드: 구성 부품, 결합 규칙과 k, 비용 후 일평균, 수익일 비율, 일간 샤프, 최대 낙폭, 비용 비중, 기여도 막대, 게이트 사유
- 종료 표시에는 §3.1의 "단계 · 사유 · 남은 예산"을 그대로 보여준다.
- 모바일 폭에서 가로 스크롤이 생기지 않게 한다.

### 3.8 의사결정 시스템 지시서와의 관계

시작할 때 `ct-decision-system-binance.md`의 구현 상태(라우터, 운용 패키지, capability registry, 롱/숏 회계)를 코드에서 확인하고 결과를 보고서에 적어라.

- **이미 구현돼 있으면:** 북을 그 운용 패키지의 한 구성으로 등록할 수 있게 연결하고, 방향은 그 capability를 따른다. 라우터를 두 개 만들지 마라.
- **아직 없으면:** 그 문서의 기능(라우터, 기준 플레이북 A/B, Binance 주문)을 이 작업에서 만들지 마라. 북은 연구·모의 경로까지만 연결한다. 실전 등록에서는 "북 실전 운용은 의사결정 시스템 작업 이후"라고 명시적으로 막아라.
- **어느 경우든** 실패한 북이나 부품을 등록 버튼으로 우회 등록할 수 없어야 한다.

## 4. 바꾸면 안 되는 것

- 최종 구간은 동결 후 한 번만 연다. 최종 성과를 어디에도 저장하지 않는 규칙도 그대로다.
- 다중검정 장부, 판 서명, 누출 규칙, 보정 기록. 오염 기록 `7a4354f4`는 모든 정책 합산에서 제외한다(행은 보존).
- 비용 프로필(측정 p90 하한), 비용 2배 스트레스, 1봉 지연, `ctGate`의 기준값. **북을 통과시키려고 기준을 낮추지 마라.**
- `traderTools ≤ 6` 계약의 모든 바이트와 동작, `ct-pattern-1/2/3` 골든 해시
- 차트 밖 우위(종목 선택, 다종목, 뉴스) 금지. 사용자 봉 주기 옵션 금지
- 모델 비용 장부(`paidCall`), 재개 시 재지불 없음, 예산 예약 비율

### 5.1 무료 검증
- §3.0 측정 보고서 완성(사전 등록 커밋이 측정 커밋보다 앞서야 한다)

### 5.2 유료 연구 (Opus 설계, 연구당 예산 $8, 총 $20 이하)
- 새 정책으로 **BTCUSDT 1분 데이터 1회, NVDA 1회**를 실행한다. 판 서명이 409를 주면 사유와 함께 진행한다.
- 확인할 것:
  1. 5/12단계에서 첫 세션 0/0 제출로 끝나지 않는다. `reflect`가 열리거나 부품이 실험된다.
  2. 부품 게이트 결과(통과·탈락 수와 사유)
  3. 북 실험 결과, 또는 북이 만들어지지 않은 정확한 이유
  4. 종료 단계·사유·남은 예산
  5. 누적 검정 수
- 북이 비용을 못 넘으면 그대로 보고한다. 결과를 좋게 보이려고 재실행하거나 실행을 골라서 보고하지 마라. 재실행했다면 모든 실행을 보고하라.

## 6. 테스트 (구현 모양을 복제하는 테스트로 대체하지 말 것)

- 정책 6 이하의 지시문·도구·안정 블록 SHA-256 고정, 정책 6에서 0/0 제출 시 기존 종료 사유 그대로
- 정책 7 분기: 0/0 → `reflect`, 0/0 연속 → 종료, 새 서명 2개 미만인 0/0 재제출 거부, 마지막 턴 통지 후에는 수용, 부품만 제출 → `experiment` → `book`
- 부품 게이트: 군집 부트스트랩이 이벤트 겹침에서 이벤트 단위 검정보다 보수적인지, 월·집중 기준, 70% 겹침 중복 제거
- 북 엔진: 같은 봉에 부품 3개가 겹쳐 켜져도 진입 비용은 한 번만 낸다. 1봉 지연과 비용 2배가 적용된다. 부품 하나짜리 북 `vote k=1`이 같은 청산 규칙의 단일 후보와 **같은 거래**를 낸다(동등성 테스트). 연구와 모의 거래 엔진이 같은 입력에 같은 거래를 낸다.
- 시점: 어떤 부품·k·청산 선택도 학습 구간 밖의 봉을 읽지 않는다(경계 직전·직후 픽스처).
- 누출: 개발·최종 수치가 설계 컨텍스트·교훈 입력·플레이북 저장 행에 나타나지 않는다(99.9 주입 테스트 방식).
- 화면 모델: 12단계 목록, 종료 문구 형식, 부품 표와 북 카드의 빈 상태

기존 테스트 기준선을 먼저 기록하라. 시작 전부터 실패하던 테스트는 커밋을 지정해 구분하라.
