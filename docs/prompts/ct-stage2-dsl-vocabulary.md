## 1. 왜 하는가

CT는 차트 단타 고수의 판단을 규칙으로 옮기는 프로젝트다. 지금 규칙 언어에는 고수가 실제로 쓰는 어휘가 빠져 있다.

- **시간 조건이 없다.** `cost_hurdle` 표는 시간대별로 결과를 보여 주는데, 규칙에는 "개장 후 30분" 같은 조건을 쓸 수 없다.
- **레벨이 없다.** VWAP, 전일 고가·저가·종가, 시가 범위(opening range), 갭, 당일 고저가 없다. 단타 셋업 대부분이 이 레벨을 기준으로 한다.
- **모든 임계값이 고정 %다.** 0.5% 하락은 조용한 날과 요동치는 날에 의미가 전혀 다르다. 변동성(ATR)으로 정규화한 표현이 없다.
- **청산이 원시적이다.** 고정 손절·고정 목표·시간 청산뿐이다. 단타의 손익은 진입만큼 청산 관리에서 갈린다.
  - 수익이 나면 손절을 본전으로 옮긴다.
  - 추세가 이어지면 트레일링으로 끝까지 따라간다.
  - 일정 시간 안에 반응이 없으면 정리한다.

  비용 장벽이 높은 판에서는 "작게 잃고 크게 먹는" 청산 구조가 특히 중요하다.

어휘가 늘면 탐색 공간이 커져 우연히 좋아 보이는 규칙도 늘어난다. 그래서 이번 작업은 어휘 추가와 함께 **검정 횟수 기록과 검토자 정보 강화**를 반드시 포함한다.

## 2. 작업 내용

모든 새 기능은 새 엔진 버전(1번에서 올린 `ct-pattern-2`, 또는 필요 시 `ct-pattern-3`)에서만 허용한다. 옛 엔진 spec은 스키마·판정·결과가 그대로여야 한다.

### 2.1 시간 조건

spec 수준에 진입 시간 창을 추가한다.

```ts
entryWindows?: Array<{ fromMinute: number; toMinute: number }> // 최대 3개
```

- 기준 시각은 시장별로 다르다. 주식은 정규장 개장 후 경과 분(0–389), 코인은 UTC 00:00 이후 경과 분(0–1439)이다.
- 신호 판정 시각(마지막 단계 완성 봉의 끝)이 창 안에 있을 때만 진입한다.
- 조기 폐장일은 실제 세션 길이를 쓴다.
- 1번의 `noEntryBeforeDayEndMinutes`와 함께 동작한다.

### 2.2 레벨 피처 (조건의 `feature`에 추가)

모두 **그 시점까지 완성된 봉만** 쓴다. 당일 값은 진행 중인 값(그 시점까지의 누적)이다.

| feature | 정의 | 비고 |
|---|---|---|
| `vwap_distance_pct` | 종가 / 당일 누적 VWAP − 1 | 주식은 세션, 코인은 UTC 일자에서 리셋 |
| `prev_day_high_distance_pct` | 종가 / 전일 고가 − 1 | 전일 = 직전 완성 세션(주식) / 직전 UTC 일자(코인) |
| `prev_day_low_distance_pct` | 종가 / 전일 저가 − 1 | |
| `prev_day_close_distance_pct` | 종가 / 전일 종가 − 1 | 개장 직후에는 갭 크기 |
| `day_open_distance_pct` | 종가 / 당일 시가 − 1 | |
| `opening_range_position` | (종가 − OR 저가) / (OR 고가 − OR 저가) | OR = 당일 첫 `lookback`분. 0–1 밖이면 돌파 상태. OR 미완성이면 null |
| `day_range_position` | 당일 고저 안 위치 0–1 | |
| `atr_pct` | 평균 진폭 / 종가 × 100 | lookback·timeframe 적용 |
| `atr_percentile` | 현재 ATR이 최근 N개 ATR 중 몇 분위인지 0–1 | 변동성 국면 판별 |

- 레벨 피처에서 `lookback`·`offset`의 의미를 피처마다 정하고, 의미가 없으면 스키마에서 고정값을 강제하라. 설계자가 의미 없는 파라미터를 탐색하지 않게 하기 위해서다.
- 차트 근거(`ctReference`)가 새 레벨을 실제 사용 기준선으로 표시하게 하라. 예: 전일 고가 선, VWAP 선, OR 박스.

### 2.3 변동성 정규화 단위

거리·수익률 계열 조건(`return_pct`, `*_distance_pct`, `range_pct`)에 단위 필드를 추가한다.

```ts
unit?: "pct" | "atr" // 기본 "pct"
```

- `atr`이면 값을 같은 timeframe의 ATR(별도 `atrLookback`, 기본 14)로 나눈 배수로 비교한다.
- 예: "VWAP 아래 1.5 ATR"을 `vwap_distance_pct` / `unit: "atr"` / `lte -1.5`로 쓸 수 있다.

### 2.4 청산 관리 (핵심)

`exit`를 다음 구조로 확장한다. 옛 필드만 있는 spec은 지금과 똑같이 동작해야 한다.

```ts
exit: {
  stop: { type: "pct" | "atr" | "pattern_low" | "swing_low", value: number },
  target?: { type: "pct" | "atr" | "r", value: number },          // r = 초기 위험 대비 배수
  breakeven?: { triggerR: number, offsetPct?: number },            // +triggerR 도달 시 손절을 진입가(+비용 상쇄 offset)로
  trail?: { type: "atr" | "swing_low" | "pct", value: number, activateR: number },
  timeStop?: { bars: number, minR: number },                       // bars 경과 시 minR 미만이면 청산
  maxHoldBars: number,                                             // 당일 경계 강제 청산은 별도로 항상 적용
}
```

규칙(반드시 지킬 것):

1. **상태가 있는 청산은 하나의 순수 함수로.**
   - `ctExitStep(spec, signal, position, bar) → { position', exit | null }`을 만든다.
   - `position`은 `entry`, `entryAt`, `initialRisk`, `highestHigh`, `stopLevel`, `breakevenArmed`, `trailArmed`를 가진다.
   - `replayCT`와 `ct-trading-engine.ts`가 **이 함수 하나만** 쓴다.
   - `ct-trading-engine.ts`의 인라인 손절 재계산(약 349행)은 `position.stopLevel`을 읽도록 바꾼다. 백테스트와 운용의 손절가가 갈라질 수 있는 경로를 남기지 마라.
2. **봉 안의 순서는 보수적으로.**
   - 한 봉에서 먼저 현재 `stopLevel`로 손절을 검사하고, 다음에 목표를 검사한다.
   - 그 봉의 고가로 `highestHigh`·본전·트레일을 갱신하는 것은 **봉이 끝난 뒤**다. 갱신된 손절은 다음 봉부터 적용한다.
   - 같은 봉에서 고가로 트레일을 올리고 같은 봉 저가로 그 트레일에 걸리는 낙관·비관 혼합을 만들지 마라.
   - 불리한 갭은 시가 체결, 손절과 목표가 같은 봉에서 동시에 닿으면 손절 먼저(현행)를 유지한다.
3. 손절은 올라가기만 한다(롱). 초기 위험 `initialRisk = entry − 초기 stopLevel`은 0보다 커야 하고, 아니면 spec 검증 단계에서 거부한다.
4. **운용 상태를 영구 저장한다.**
   - 모의·실전 거래 레코드에 `position` 상태를 저장한다.
   - 러너가 재시작하면 저장된 상태에서 이어 가거나, 저장된 관측 봉(`ct_trade_charts`)으로 진입 시점부터 결정적으로 재계산한다.
   - 두 방식의 결과가 같다는 테스트를 둔다.
5. 스트레스 테스트의 "손절 ±10%"는 초기 손절 거리(`stop.value`)에 적용한다. 트레일·본전 파라미터는 그대로 둔다. 이 정의를 `docs/ct.md`에 명시한다.
6. 거래 기록과 차트에 청산 사유(`stop`/`breakeven`/`trail`/`target`/`time_stop`/`max_hold`/`day_end`)와 손절선 이동 이력을 남긴다.

### 2.5 설계 도구 갱신

1. `query_conditional_returns`가 새 피처, `unit`, `entryWindows`를 받는다.
2. 손절·목표 격자에 청산 모드 비교를 추가한다. 같은 이벤트 집합에 대해 다음 결과를 나란히 돌려준다(학습 구간만).
   - 고정 손절·목표
   - 본전 이동
   - 트레일
   - 시간 손절

   각 결과는 비용 후 기대값, 일평균, 승률, 평균 R, 비용 2배 기대값이다. 격자 크기는 상한을 둔다.
3. `screen_rule`이 새 spec을 받는다.
4. `ctRuleText`가 새 요소를 사람이 읽는 한국어로 쓴다.
5. `CT_DESIGNER_SYSTEM`의 규칙 언어 문단을 갱신한다.
   - 새 어휘를 나열하는 데서 그치지 말고, 각 어휘를 언제 쓰는지와 왜 그런지(단타 관점)를 짧게 설명한다.
   - "청산 구조로 비용을 이기는 방법"을 비용 장벽 설명 바로 뒤에 둔다.
   - 도구 정의와 시스템 프롬프트 바이트가 실행 중 바뀌지 않게 해서 캐시를 유지한다.

### 2.6 다중 검정 장부

1. 설계 세션의 모든 `query_conditional_returns`·`screen_rule` 호출에서 "실질적으로 다른 가설 검정 수"를 센다. 같은 조건 집합의 임계값 변형도 1회로 센다. 연구 단위로 누적한다.
2. 검정 수를 설계자 컨텍스트(매 턴 결과에 짧게)와 위험·증거 검토자에게 전달한다.
3. 검토자 지시에 추가할 것: 검정 수 대비 개발 결과의 유의성을 판단하라. 어휘가 늘었으니 단순한 규칙을 선호하라.
4. 후보의 "자유도"(조건 수 + 청산 파라미터 수)를 계산해 결과 요약과 검토 입력에 표시한다. 게이트는 바꾸지 않는다.

## 3. 바꾸면 안 되는 것

- 1번 지시서 3절의 불변 조건 전부. 특히 게이트 완화 금지, 롱 전용, 당일 청산, 1분봉 백테스트, 시간순 60/20/20, 최종 구간 1회 평가.

- 표현할 수 없는 조건을 설명에만 넣어 통과시킬 수 없다(현행 규칙 유지).

## 4. 테스트

1. 피처마다 **미래 불변성**: 시점 t의 피처값이 t 이후 봉을 추가해도 변하지 않는다(합성 데이터, 피처 전부).
2. VWAP·당일 고저·OR의 리셋 경계(주식 세션, 코인 UTC 일자), 조기 폐장, OR 미완성 시 null.
3. 전일 레벨이 직전 완성 세션만 쓰고, 분할 경계를 넘지 않는다.
4. `unit: "atr"` 변환값을 수기 계산과 대조한다.
5. `entryWindows` 경계값(포함·제외)을 확인한다.
6. `ctExitStep`:
   - 본전 이동, 트레일 활성화·상승 전용, 시간 손절, 갭 하락 시가 체결.
   - 같은 봉에서 트레일 갱신 후 같은 봉 저가 미적용.
   - `initialRisk ≤ 0` 거부.
7. **백테스트·운용 동일성**: 같은 봉 열에서 `replayCT`의 거래와 모의 엔진의 청산 시각·가격·사유가 일치한다. 러너 재시작 후 재계산 결과도 같다.
8. 옛 spec 회귀(`ct-pattern-1`, 1번 이후 `ct-pattern-2` 옛 필드 spec).
9. 검정 수 집계: 임계값 변형은 1회, 다른 feature 조합은 별도로 센다.
10. 진행 화면·차트가 새 청산 사유와 손절선 이동을 표시한다(`tests/ct-activity.test.mjs` 등 확장).

## 5. 실제 실행 검증

1. `npm run local`로 앱·러너를 띄우고, CT → 코인(기본 종목·기간)으로 **전략 생성**을 실제로 끝까지 실행한다.
2. 보고할 것:
   - 설계자가 새 어휘(시간 창, 레벨, ATR 단위, 청산 관리)를 실제로 몇 번, 어떻게 썼는지.
   - 청산 모드 비교 결과 중 대표 사례 2–3개.
   - 검정 수, 후보 자유도.
   - 후보 수 → 학습 통과 → 개발 통과와 탈락 사유.
   - 비용.
   - 1번 작업 후 실행과의 비교표.
3. 통과 후보가 나오면 차트에서 손절선 이동과 레벨 기준선이 맞게 보이는지 스크린샷으로 확인한다.
4. 가능하면 주식(NVDA)도 1회 실행한다. 레벨 피처(VWAP·전일 고가·OR)는 주식에서 의미가 크다.
