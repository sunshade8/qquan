## 배경 (왜 하는가)

- CT(1분봉 차트 단타 연구 에이전트)는 약 30회 연구에서 통과 후보가 0개였다. 모델 비용 없이 한 천장 측정 4회(64·140·192·336 조합)도 모두 "후보 없음"이었다. 근거: `docs/ct.md`, `docs/research/ct-ceiling-*.md`.
- 프로젝트에서 표본 밖 성과와 비용 2배를 모두 견딘 규칙은 2026-09의 **H2 하나**다. 3거래일 −6% 급락 종목을 낙폭 순으로 하루 최대 3개 사서 5거래일 보유하고, 손절은 −6%다. 11년 3,144거래에서 거래당 순수익 +0.852%, 날짜 군집 t 4.6, OOS +1.40%였다. 근거: `docs/research/results-2026-09.md`, `docs/research/adopted-rules-2026-09.md`, 구현 `lib/trade-strategies.ts`의 `h2Reversal`, 스크립트 `scripts/research/`.
- **의심 지점:** 유니버스가 `lib/universe.ts`의 `megacap ∪ nasdaq_tech`(57종목)다. 이것이 **현재 시점의 목록을 2015년까지 소급한 것**이라면, "결국 살아남아 대형주가 된 종목"만 담은 셈이다. 급락 반전 전략은 이 편향에 특히 취약하다. 급락 후 회복하지 못하고 사라진 종목이 표본에서 빠지기 때문이다.
- 다음 방향(소유자 결정): 종목 선정을 연구에 넣는다. 대형주에는 오히려 우위가 없을 수 있다. 판 고르기는 한 번(또는 분기 1회) 측정으로 하고, "오늘의 종목"은 백테스트 가능한 규칙으로 만든다. 그러려면 **과거 시점 기준(point-in-time)의 전 종목 데이터**가 있어야 한다.

## 파트 1 — H2 생존자 편향 재검증

### 1.1 사전 등록 (측정 전에 쓰고 커밋)

`docs/research/h2-survivorship-YYYY-MM-DD.md` 맨 앞에 판정 기준을 쓴다. **결과를 본 뒤 기준을 바꾸지 않는다.** 커밋이 불가능한 환경이면 작성 시각과 파일 SHA-256을 문서에 기록한다.

- 비교 대상: 원래 결과(현재 목록 유니버스)와 **시점별 유니버스** 결과를 같은 규칙·같은 비용(`lib/broker-costs.ts` `roundTripPct()`)·같은 체결 규약(다음 거래일 종가, 손절 장중 판정, 같은 봉에서 손절·목표가 모두 닿으면 손절 우선)으로 비교한다.
- "H2 유지" 조건(모두 만족): 시점별 유니버스에서 ① 거래당 순수익 > 0, ② 날짜 군집 t ≥ 2.0, ③ OOS(최근 12개월) 거래당 순수익 > 0, ④ 비용 2배에서도 거래당 순수익 > 0.
- "H2 약화" = ①은 통과하고 ②~④ 중 하나 이상 실패. "H2 기각" = ① 실패.
- 편향 크기 = (원래 거래당 순수익 − 시점별 거래당 순수익). 이 값도 함께 보고한다.

### 1.2 할 일

1. `lib/universe.ts`가 정적 목록인지, 시점별 구성인지 코드로 확인한다. 2026-09 스크립트가 어느 유니버스로 돌았는지도 확인하고, 원래 결과를 재현해 같은 숫자가 나오는지 먼저 본다.
2. 시점별 유니버스를 만든다. 예: 매년(또는 분기) 초 시점의 시가총액·거래대금 상위 N개, **상장폐지·편출 종목 포함**. 기준과 N은 사전 등록에 적는다. 원래 유니버스 크기(57)와 비슷하게 맞춘다.
3. 데이터가 2015년까지 없으면 다음 순서로 시도한다.
   - (a) 확보 가능한 기간만으로 재검증하고, 기간이 줄었다고 명시한다.
   - (b) 2015년 당시 대형주였다가 지금 목록에서 빠진 종목을 공개 자료로 수집한다(지수 구성 변경 이력 등). 출처를 링크하고, 그 종목들을 추가했을 때의 결과를 하한 추정으로 낸다.
   - (c) 둘 다 불가능하면 불가능하다고 쓰고, 편향 크기의 상한·하한을 어떻게 추정했는지 근거와 함께 쓴다.
4. 원래 표(`results-2026-09.md`의 H2 행)와 나란히 표로 보고한다. 거래 수, 승률, 거래당 순수익, 날짜 군집 t, OOS, 비용 2배, MDD를 포함한다.

### 1.3 주의

- 군집 t는 진입 날짜로 군집해서 계산한다(`docs/research/results-2026-09.md`의 방법 교정).
- 수정주가와 상장폐지 종목의 마지막 가격 처리 방식을 명시한다. 상폐 직전 보유 종목이 있으면 **마지막 거래 가격으로 청산**하고, 그 처리가 결과를 얼마나 바꾸는지도 적는다.
- `lib/price-cache.ts`·`lib/market-data.ts`·`lib/massive.ts`는 `cloudflare:workers`를 import하므로 Node 스크립트에서 쓸 수 없다. `scripts/research/_load.ts` 방식을 따른다.

## 파트 2 — 종목 판 데이터 확인 (모델 비용 $0, 읽기 전용)

목표는 "앞으로 어떤 판을 측정할 수 있는가"를 표 하나로 답하는 것이다. 전략을 만들지 않는다.

### 2.1 확인할 것

| 질문 | 확인 방법 |
|---|---|
| Massive(Polygon 기반)로 **특정 과거 날짜의 전 종목 일봉**(그날 거래된 종목 전부, 이후 상폐 종목 포함)을 받을 수 있나 | grouped daily 집계 엔드포인트(Polygon 의미론)를 실제 키(`.dev.vars`의 `MASSIVE_API_KEY`, 없으면 `POLYGON_API_KEY`)로 호출. 최근 날짜 1개, 2년 전 날짜 1개, 5년 전 날짜 1개 |
| 상폐 종목의 메타데이터(티커, 상폐일)를 받을 수 있나 | 티커 참조 엔드포인트를 `active=false`·`date=` 등으로 호출해 과거 시점 목록이 나오는지 |
| 분봉은 어디까지 되나 | 소형주 1개와 상폐 종목 1개로 1분봉 요청. 2024-10-12 이전이 403인지 재확인 |
| 현재 플랜과 레이트리밋 | 응답 헤더·오류 메시지로 확인. 5회/분이었던 기록이 지금도 맞는지 |
| Yahoo 일봉으로 상폐 종목을 받을 수 있나 | 상폐 종목 2–3개로 시도 |

- **Polygon `limit` 함정:** `limit`는 반환 행 수가 아니라 스캔하는 기본 단위의 상한이다. 작은 값으로 찍으면 `resultsCount 0`이 나온다. 항상 `limit=50000`으로 확인한다.
- 키 값은 출력·문서·로그·URL에 남기지 않는다.

### 2.2 산출물

`docs/research/universe-data-availability-YYYY-MM-DD.md`에 다음을 쓴다.

1. 위 질문마다 됨/안 됨/부분적, 실제 요청 예시(키 제외), 응답 요약.
2. 측정 가능한 판의 목록과 각각의 가능 기간. 예: "미국 전 종목 일봉, 생존자 편향 없음, 2년", "소형 급등주 1분봉, 2년".
3. 불가능한 판과 그 이유. 필요한 데이터 제공자나 플랜이 무엇인지도 적는다(가격 조사는 하되 결제나 가입은 하지 않는다).
4. **선택 항목(소유자 확인 후에만):** 소형 급등주의 스프레드를 토스 시세·호가 API로 읽기 전용 측정할 수 있는지. 토스 토큰을 새로 발급하면 이전 토큰이 폐기되어 실행 중인 dev 서버가 끊긴다. 토큰 재발급이 필요하면 하지 말고 보고만 한다.
