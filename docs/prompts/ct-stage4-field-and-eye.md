### 2.2 `contrast_moves`에 방향을 묻는 대조군 (A-2)

입력에 `controls: "time" | "vol_matched" | "losers"`를 추가한다. 기본값은 기존 동작인 `"time"`이다.

- **`time`**(기존): 같은 시(하루 시작 후)·같은 달, 라벨 무관. 결과는 바이트 단위로 지금과 같아야 한다.
- **`vol_matched`**: `time`의 조건에 **같은 변동성 5분위**를 더한다.
  - 변동성 = 결정 시점에 완성된 60분봉 ATR(14)를 가격으로 나눈 값.
  - 5분위 경계는 학습 구간의 유효 순간 전체 분포로 정한다.
  - 사건 대표 시각의 5분위와 같은 칸에서 사건당 3개를 시드 고정으로 뽑는다.
  - 어떤 칸에 후보가 부족하면 그 사건은 대조군 없이 버리고, 버린 수를 결과에 적는다.
- **`losers`**: 같은 라벨에서 **손절이 목표보다 먼저 닿은 순간**(`MOVE_REASON.stop`)을 음성 사건으로 묶어 대조군으로 쓴다.
  - 묶음 규칙과 대표 시각(중앙값 순간)은 양성 사건과 같다.
  - 시·달·변동성 5분위를 양성 사건 쪽에 맞춰 사건당 1개 이상 뽑는다(비율은 결과에 적는다).
  - 이 모드의 lift는 "같은 시각·같은 변동성에서 위로 갔는가, 아래로 갔는가"의 차이다.

모드 공통:
- 결과에 `controlMode`, 대조군 수, 버린 사건 수, 매칭 규칙 문장을 넣는다.
- 피처마다 lift의 모양을 서버가 분류해 붙인다: `monotone_up` / `monotone_down` / `two_tailed` / `flat`. 기준(예: 양 끝 5분위의 lift와 z)을 코드 주석과 문서에 적는다.
- 트리(`tree: true`)는 선택한 대조군을 음성 클래스로 쓴다. 앞 2/3 → 뒤 1/3 홀드아웃 규칙은 그대로다.
- `contrastId`의 해시에 `controlMode`를 넣는다. 근거 규칙(같은 feature·timeframe)은 그대로다.
- 다중 검정 장부의 서명에 모드를 넣는다. 같은 feature·5분위라도 모드가 다르면 다른 가설이다(`ctContrastSignatures`).
- 학습 경계 규칙은 그대로다. 앞을 내다보는 구간이 `trainingToMs`를 넘는 순간은 대조군에서도 버린다.

새 지시문(`CT_DESIGNER_SYSTEM` 4단계)에 이유를 설명한다(강제하지 않는다). 담을 내용:
- 시간만 맞춘 대조군에서 양쪽 꼬리 lift가 함께 오르면 변동성 효과다.
- 롱 전용에서 방향을 물으려면 `losers`나 `vol_matched`를 쓴다.
- lift는 여전히 단서일 뿐이고, 확인은 `query_conditional_returns`와 `screen_rule`로 한다.

### 2.3 같은 데이터에서 이미 잰 것을 보여 주기 (A-3)

- 같은 소유자, 같은 시장·종목, 같은 학습 경계, 같은 데이터 해시에서 이전 실행이 이미 부른 `label_moves`(파라미터)와 `contrast_moves`(라벨 파라미터, 특징 목록, 모드)를 모은다. 각 항목에 요약 한 줄과 그 실행이 내린 결론(세션 `noEdgeReason` 첫 문장 또는 기각 가설 결과)을 붙인다.
- 이 목록을 설계 세션 **안정 블록**에 "이 학습 데이터에서 이미 측정된 것"으로 넣는다. 실행 시작 때 한 번 고정해 재개해도 같게 한다(`playbook_summary`처럼 도구 캐시를 쓴다).
- 누출 규칙: 학습 구간 측정만 대상이므로 수치를 보여 줘도 된다. 개발·최종 결과는 넣지 않는다.
- 설계자가 같은 파라미터의 `label_moves`를 다시 부르면 결과는 그대로 주되 `previouslyMeasured: [{ runId, conclusion }]`를 붙인다. 계산은 무료이므로 막지는 않는다.
- 장부: 이전 실행에서 같은 서명으로 이미 센 검정을 이 실행에서 다시 셀지 정하고 문서화한다. 권장은 "이 실행 장부에는 세고, 누적 검정 수에는 중복 합산하지 않음"이다.

### 2.4 계약 문구 버그 (A-4)

- `prepareCTContract`의 `selection` 기본 문구를 시장별로 나눈다.
  - 코인: "Binance BTCUSDT(또는 선택 종목) 연구 · 다른 종목에 일반화 검증되지 않음"
  - 주식: 기존 NVDA 문구
- 이미 저장된 계약은 고치지 않는다. 화면에 보여 줄 때만 시장에 맞지 않는 문구를 보정하고, 그 사실을 주석으로 남긴다.

### 2.5 설계자의 눈: 보정 기록 분리와 큰 블라인드 세트 (차트 1·2번)

**보정 기록을 메커니즘 기각과 분리한다.**
1. `grade_blind` 결과는 서버가 직접 **보정 기록**으로 저장한다.
   - 새 테이블 `ct_calibration`(`ensureSchema` 패턴)을 두거나, 플레이북에 별도 종류를 둔다. 둘 중 하나를 고르고 이유를 적는다.
   - 필드: 시장, 종목, 실행 id, 세트 크기 n, 적중 k, p값, 판정, 측정 기간, 차트 형식 버전.
2. **판정 규칙(서버 계산):**
   - `skill`: p < 0.05
   - `no_skill`: p ≥ 0.05이고, 실제 정확도 70%를 검정력 0.8 이상으로 잡을 만큼 n이 컸다
   - `inconclusive`: 그 밖
   - `grade_blind` 결과에 판정, 검정력(70%·75% 가정), 이 n에서 유의에 필요한 적중 수를 함께 돌려준다.
3. 설계 세션 안정 블록에는 보정 기록을 메커니즘 플레이북과 다른 절로 보여 준다. 판정과 n을 함께 보여 주고, `inconclusive`는 "표본이 작아 판정 불가"로 읽힌다고 설명한다.
4. 설계자가 `rejectedHypotheses`에 눈·차트 판별력 자체를 넣는 경우를 처리한다. **서버가** 플레이북의 `rejected_in_training` 대신 보정 기록 참조로 바꾼다.
   - 판별 기준: 그 항목의 `evidence`가 `blindId`만 가리키는 경우다. `rejectedHypotheses`에 실제로 어떤 값이 들어갔는지 저장된 `bcf289ab` 세션 메시지에서 먼저 확인하라.
   - 텍스트 키워드 판별은 쓰지 마라. 근거로 판별할 수 없으면 새 지시문에서 "보정 결과는 기각 가설이 아니다"라고 설명하는 것으로 대신하고, 그 한계를 보고하라.
5. **이미 저장된 행을 이전한다.**
   - `bcf289ab-41d9-4bc7-9598-824276520eb8:rej:0:4`를 보정 기록(n 8, k 6, p 0.145, `inconclusive`)으로 옮긴다.
   - `f8aeaf03`의 블라인드 결과(n 8, k 4, p 0.637)가 플레이북에 같은 식으로 들어가 있으면 같이 옮긴다.
   - 소급 기록(`backfillPlaybook`)을 다시 돌려도 기각 행으로 되살아나지 않아야 한다(결정적 id 규칙을 확인하라).
   - 이전은 마이그레이션 코드로 하고, 수동 SQL로 하지 않는다.
6. 이번 변경은 플레이북을 읽는 모든 실행(이전 정책 포함)에 적용된다. 이전 정책 계약을 재개할 때는 안정 블록이 이미 도구 캐시로 고정되어 있으니 바뀌지 않는다. 이것을 테스트로 확인하라.

**블라인드 세트를 키운다(새 정책만).**
1. `view_charts`의 `blind: true` 세트 크기:
   - 최소 16장, 기본 24장, 최대 32장. 이벤트와 대조군을 같은 수로 섞는다.
   - 일반 모드는 지금처럼 호출당 8장 이하다.
2. 세션 이미지 한도를 측정 근거로 조정한다. 블라인드 24장과 일반 16장이 들어가도록 48장을 제안한다.
   - 요청당 이미지 수·크기 한도를 공식 문서로 확인한다. 이전 턴의 이미지는 매 요청에 다시 실린다.
   - 한도를 넘는다면 해상도를 낮춘 블라인드 전용 렌더(예: 1분봉 패널만)를 검토하고, 측정한 토큰과 함께 보고하라.
3. 블라인드 세트에 쓸 앵커가 부족하면(`label_moves` 대표 12개와 대조군 12개) `label_moves`가 블라인드용 예비 앵커를 더 발급하게 한다.
   - 대표 시각 규칙과 시드는 같다.
   - 일반 보기에 이미 쓴 앵커는 블라인드 세트에서 뺀다. 설계자가 정답을 이미 본 차트를 다시 맞히지 않게 하기 위해서다. 서버가 검사한다.
4. `grade_blind`의 예측 수 상한(지금 64)과 세트 크기를 맞춘다.
5. 비용 예약(`lib/designer-request-size.ts`의 이미지당 토큰 가정)과 실제 측정치(3단계 실측: 장당 약 900토큰)를 다시 확인한다.

### 2.6 설계자의 생각 기록 (차트 4번)

1. **원인을 먼저 확정한다.** 둘 중 무엇인지, 또는 둘 다인지 실제 요청 1회로 확인하라.
   - (a) Opus 5.5의 adaptive thinking 기본 `display`가 생각 내용을 생략(`omitted`)한다. SDK 타입 주석은 기본이 `summarized`라고 하지만 모델별 기본값을 공식 문서로 확인하라.
   - (b) `streamClaude`가 `thinking_delta`를 누적하지 않는다.
   - 확인용 호출은 최소 크기로 하고 비용을 보고하라.
2. **고친다.**
   - 새 정책 계약의 설계 세션 요청에 `thinking: { type: "adaptive", display: "summarized" }`를 명시한다(원인이 (a)인 경우).
   - 원인이 (b)라면 스트림 누적을 고친다.
   - 이전 정책 계약의 재개 요청은 바이트 단위로 그대로 둔다.
   - preserved thinking 규칙은 그대로다. assistant `content`는 받은 그대로 저장하고 다음 요청에 그대로 붙인다.
   - 표시 방식 변경이 캐시 적중과 청구 토큰에 주는 영향을 측정해 보고하라.
3. **보여 준다.**
   - 진행 화면의 설계 세션 섹션에서 턴마다 "설계자 생각(요약)"을 접이식으로 보여 준다.
   - 원문은 `ct_session_messages`에 이미 있으니 새 저장소를 만들지 않는다.
   - 생각이 비어 있으면 "기록 없음(이 계약은 생각 요약을 받지 않음)"으로 표시한다.
4. 위험·증거 검토자 입력에는 넣지 않는다. 길이와 독립성 때문이다. 이 결정을 문서에 적는다.

### 2.7 천장 측정 확장 (2부, 모델 비용 $0)

`scripts/research/ct-ceiling.ts`를 확장한다. 방법(라벨, 확장 창 워크포워드 4폴드, 깊이 ≤ 3 트리, 학습 잎 선택, 일평균 정의, 비용 2배 열)은 **바꾸지 않는다**. 바꿔야 하면 이유를 먼저 적고 이전 방법의 결과도 함께 낸다.

**측정 전에 판정 기준을 등록한다.** 아래 기준을 결과 문서 맨 앞에 먼저 쓰고 커밋한 다음 측정을 돌린다. 결과를 본 뒤 기준을 바꾸지 마라.

> 조합이 "유료 연구 후보"가 되려면 다음을 모두 만족해야 한다.
> - 비용 1배 워크포워드 일평균 > 0
> - 양수 폴드 ≥ 3/4
> - 선택 거래 ≥ 0.27건/일(개발 구간 73일에서 게이트 최소 20건)
> - 비용 2배 일평균 > 0
> - 아래 순열 기준선을 통과

**순열 기준선:** 후보 조건을 만족한 조합에만 적용한다. 일 단위 블록으로 피처 행을 섞는 순열을 20회 돌리고, 실제 일평균 이상이 나온 횟수를 보고한다(20회 중 1회 이하일 때 통과).

#### B-1. 종목: ETH·SOL

- `ETHUSDT`, `SOLUSDT`(로컬 parquet `eth`, `sol`)를 BTC와 같은 표로 잰다. 기간은 1년, 3년이다.
- 비용은 `ct_orderbook_samples`의 Binance 종목별 실측을 쓴다. 지금 스크립트는 BTCUSDT 쿼리가 하드코딩되어 있으니 고친다.
  - 참고: 2026-10-14 시점 평균 스프레드는 BTC 0.0bp, ETH 0.04bp, SOL 0.93bp다.

#### B-2. 실행 거래소 비용: Upbit

- 실제 실행 거래소는 Upbit KRW 현물이다. 비용은 수수료 0.05% × 2(`lib/ct-costs.ts` `upbit-krw` v2)에 Upbit 실측 스프레드·충격을 더한다.
  - 2026-10-14 평균 스프레드: KRW-BTC 2.66bp, KRW-ETH 4.82bp, KRW-SOL 10.46bp.
- **B-2a:** 이 비용을 Binance 가격 경로에 적용한 행을 낸다. 가격 경로가 Upbit와 다르다는 근사임을 표에 명시한다.
- **B-2b:** B-5에서 Upbit 1분봉을 받으면 Upbit 가격 경로와 Upbit 비용으로도 잰다.

#### B-3. 기간

- 모든 종목에 1년과 3년을 낸다. 로컬에 5년이 있으니 BTC는 5년도 한 줄 낸다.
- 지금의 1년 학습 구간이 하락 국면 하나뿐이라는 점(1.5)을 감안해, 국면별로 쪼갠 결과는 따로 보고한다. 예: 일봉 SMA200 위·아래 날짜별 일평균.

#### B-4. 파생 데이터 피처 (가장 중요)

Binance USDⓈ-M 선물의 공개 과거 데이터를 받는다(인증 없음).
- 펀딩비
- 프리미엄 지수(선물–현물 괴리) 1분봉
- 미결제약정과 테이커 매수/매도 비율 등 지표(5분)
- 강제청산 기록: 과거치가 공개되어 있으면

받을 곳은 data.binance.vision 같은 공개 아카이브 또는 공식 REST다.
- **실제로 어떤 항목이 몇 년치 있는지, 타임스탬프가 기간 시작인지 끝인지를 실제 파일로 확인하고 표로 남겨라.**
- REST의 과거 조회 한도(예: 일부 지표는 최근 30일만)도 확인하라.

다운로드:
- `scripts/data/download-binance-derivs.py`를 만든다. `download-btc-minute.py` 패턴(재개, 해시, `~/.qquan/parquet/…`, catalog 등록)을 따른다.
- BTC·ETH·SOL, 최근 3년(가능한 범위)을 받는다.
- 파일 체크섬이 제공되면 검증한다.

피처(천장 측정 전용, DSL에는 넣지 않는다):
- 펀딩비 수준과 직전 정산 대비 변화
- 프리미엄 % 수준, 15·60분 변화, 7일 z점수
- 미결제약정 60·240분 변화율과 z점수
- 테이커 매수/매도 비율
- (있으면) 직전 60분 강제청산 규모

**시점 규칙:** 결정 시각에 이미 공개된 값만 쓴다. 5분 지표는 완성된 구간만, 펀딩비는 정산 시각 이후에만 쓴다. 시각 의미는 위에서 확인한 대로 적용하고, 미래 값 미사용을 테스트로 고정한다.

**기여도(ablation):** 같은 폴드에서 피처 집합을 바꿔 잰다.
1. 가격·거래량 31개(현재)
2. 1 + 파생
3. 2 + 괴리(B-5)

차이를 표로 낸다. 선택된 잎에 어떤 피처가 쓰였는지도 집계한다.

#### B-5. Upbit–Binance 괴리와 선후행

1. Upbit 공개 시세 API(인증 없음)로 KRW-BTC와 KRW-USDT 1분봉을 최근 1년 받는다. 시간이 되면 KRW-ETH도 받는다.
   - 페이지 크기, `to` 파라미터 의미, 요청 제한을 공식 문서(`docs.upbit.com`)로 확인하고 지켜라.
   - 재개 가능하게 하고 `~/.qquan/parquet/upbit/…`에 둔다.
   - 빈 분(거래 없음)을 어떻게 다룰지 정해 문서화한다.
2. **괴리(%)** = Upbit KRW-BTC ÷ (Binance BTCUSDT × Upbit KRW-USDT) − 1. 같은 분의 완성 봉 종가로 계산한다.
3. 피처:
   - 괴리 수준, 15·60분 변화, 7일 z점수
   - Binance 직전 1·3·5분 수익률 − Upbit 같은 구간 수익률(선후행)
4. 라벨은 **Upbit 가격 경로와 Upbit 비용**으로 만든다(B-2b). 실행이 Upbit에서 일어나기 때문이다.

  - 시간순 60/20/20, 최종 구간 1회 평가
- 모든 설계 도구는 학습 구간 전용이다. 새 대조군 모드도 같다.
- 설계자에게 개발 구간은 요약 수치만, 최종 구간은 아무것도 주지 않는다. 보정 기록과 "이미 측정된 것" 목록도 이 규칙을 따른다.
- 독립 검토자는 설계자와 다른 회사(`assertDifferentProvider`)다.
- 이전 정책 계약(`traderTools` 없음 또는 1)의 시스템 지시, 도구 정의, 요청 옵션은 바이트 단위로 그대로 둔다. SHA-256 테스트로 고정한다.
- preserved thinking, 턴 단위 비용 장부, 재개 시 재지불 없음.
- 실주문 도구를 만들지 않는다. 2부 다운로드는 공개 시세·아카이브만 쓰고 인증 API를 부르지 않는다.
- **백그라운드 호가 샘플러(`npm run data:orderbook -- --hours=72`, 2026-10-16 17:41Z 종료 예정)를 멈추지 마라.** 2부는 그 시점까지 쌓인 표본을 쓰고, 프로필이 잠정(`provisional`)임을 표에 적는다.
- 파생·괴리 피처를 DSL이나 설계 도구에 넣지 않는다(이번 범위 밖).

## 4. 테스트

1. **판 서명**
   - 같은 입력이면 같은 서명이다. 종목 순서와 공백 차이에는 무관하다.
   - 경계, 비용, 정책 버전, 데이터 해시, brief가 다르면 다른 서명이다.
   - 같은 서명의 완료(통과 없음)·진행 중 실행이 있으면 유료 호출 전에 409로 거부되고, 모델 호출 0회다.
   - `repeatReason`이 있으면 진행되고 사유가 계약과 검토자 입력에 실린다.
2. **`contrast_moves` 대조군**
   - `time` 결과가 변경 전 골든 결과와 바이트 동일하다.
   - `vol_matched` 대조군의 시·달·변동성 5분위가 사건과 일치한다.
   - `losers`가 손절 먼저인 순간만 쓰고 묶음·대표 시각 규칙이 양성과 같다.
   - 합성 시장 검증: 변동성만 다른 합성 데이터에서는 `time` 모드가 `two_tailed`, `vol_matched`가 `flat`으로 분류된다. 방향 신호를 심은 합성 데이터에서는 `losers`가 그것을 `monotone_*`으로 찾는다.
   - 모드별 `contrastId`와 장부 서명이 다르다.
   - 학습 경계 밖 순간은 제외된다.
3. **이미 측정된 것**
   - 같은 학습 데이터의 이전 실행 라벨·contrast가 안정 블록에 들어간다.
   - 개발·최종 수치는 들어가지 않는다.
   - 재개해도 같다.
   - 같은 라벨 재호출에 `previouslyMeasured`가 붙는다.
4. **계약 문구:** 코인 계약에 NVDA 문구가 들어가지 않는다.
5. **보정 기록**
   - `grade_blind` → 보정 기록 저장, 판정(`skill`/`no_skill`/`inconclusive`)과 검정력 계산이 맞다(1.3의 표 값과 일치).
   - `blindId`만 근거로 둔 기각 가설은 플레이북 기각 행이 아니라 보정 기록 참조가 된다.
   - 기존 행 이전이 멱등이다. 소급 기록을 다시 돌려도 기각 행이 되살아나지 않는다.
6. **블라인드 세트**
   - 새 정책에서 16–32장 균형 세트가 허용되고, 이전 정책은 8장 한도 그대로다.
   - 일반 보기에 쓴 앵커는 블라인드 세트에 못 들어간다.
   - 세션 이미지 한도와 블라인드 세트 수 한도가 적용된다.
   - 이미지가 든 tool_result가 다음 턴 요청에 바이트 그대로 실린다(모의 fetch).
7. **thinking**
   - 새 정책 요청에만 `display` 옵션이 들어가고, 이전 정책 요청은 변경 전과 바이트 동일하다.
   - 요약 생각이 들어 있는 fixture가 진행 화면 데이터(`lib/ct-activity.ts`)에 턴별로 나온다.
   - 원인이 스트림 누적이었다면 `thinking_delta` 누적 테스트를 둔다.
8. **시스템 지시 해시:** `CT_DESIGNER_SYSTEM_STAGE2`, `CT_DESIGNER_SYSTEM_STAGE3`의 SHA-256 고정 테스트.
9. **천장 측정 확장**
   - 파생 지표·괴리 피처가 결정 시각 이후 값을 쓰지 않는다(미래 값을 오염시켜도 피처가 같다).
   - Upbit 빈 분 처리.
   - 종목별 비용 조회.
   - 순열 기준선의 시드 재현.
10. 기존 테스트 전체(`node --experimental-strip-types --test tests/*.test.mjs`)가 깨지지 않는다. 변경 전에 이미 실패하던 테스트가 있으면 변경 전 결과를 먼저 기록해 두고 구분해 보고하라.

## 5. 실제 실행 검증

### 5.1 1부: 실데이터, 모델 비용 $0

1. `npm run local`로 앱·러너를 띄운다.
2. CT → 코인 → 기본값(BTCUSDT · 365일)으로 전략 생성을 누른다. 기존 실행 `3ab2ad6c`와 같은 판이므로 새 정책 버전 때문에 서명이 달라질 것이다. 다음을 실제 화면과 API로 확인한다.
   - 이전 정책 버전으로 같은 판을 시작하면 409와 안내가 나오는지 확인한다. 테스트용 경로나 플래그로 한다. 모델 호출은 0회여야 한다.
   - 화면에 거부 메시지와 사유 입력이 보이는지 확인한다.
3. 스크립트로 BTCUSDT 학습 구간(2025-10-13–2026-05-20)에서 `contrast_moves`를 세 모드로 돌린다. 라벨은 k5 · m2 · 240봉, 특징은 `3ab2ad6c`와 같은 8개다. 서버 함수를 직접 부르면 모델 비용 없이 된다.
   - 모드별 lift 표와 모양 분류를 보고한다.
   - 1.2의 "양쪽 꼬리" 결론이 `vol_matched`·`losers`에서 어떻게 바뀌는지 적는다.
4. 플레이북 화면과 설계 세션 안정 블록에서 `bcf289ab` 블라인드 항목이 기각 목록이 아니라 보정 기록(`inconclusive`, n 8)으로 보이는지 확인하고 스크린샷을 남긴다.

### 5.2 1부: 유료 연구 1회

1. **ETHUSDT · 365일 · 예산 $8**로 새 정책 연구를 1회 끝까지 실행한다. 아직 연구하지 않은 판이라 새 정보도 된다.
2. 버그로 중단된 경우에만 고친 뒤 1회 더 실행할 수 있다. 그 밖의 반복 실행은 하지 마라.
3. 보고할 것:
   - 설계 세션별 도구 순서와 횟수, `contrast_moves`의 모드 선택
   - 블라인드 세트 크기·적중·p·판정, 본 차트 수, 이미지 입력 토큰·캐시 읽기 토큰
   - **설계자 생각 요약이 실제로 저장·표시되는지**(스크린샷). 그리고 차트를 보거나 건너뛴 이유, 멈춘 이유가 생각 요약에 어떻게 나타나는지 인용 2–3개
   - 역할별 비용, 총비용($8 대비)
   - 후보 수 → 학습 통과 → 개발 통과, 탈락 사유
   - `3ab2ad6c`와의 비교표
4. 설계자가 블라인드 세트를 쓰지 않았다면 그 사실과 생각 요약에 나타난 이유를 보고한다. 강제로 쓰게 만들지 마라.
