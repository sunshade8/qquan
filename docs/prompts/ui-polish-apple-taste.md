## 0. 왜 하는가

기능을 단계마다 덧붙이면서 화면이 복잡해졌다. 특히 CT(`app/ct-*.tsx`, `app/ct.css`)와 그 복제본 T(`app/t-*.tsx`)가 심하다. CT는 `ct-workspace.tsx` 1,313줄, `ct-progress.tsx` 715줄, `ct-validation.tsx` 851줄이고, 11단계 스테퍼, 에이전트 카드 6개, 비용 미터, 활동 피드, 플레이북, 교훈, 보정 기록 등이 한 화면에 쌓여 있다.

목표는 **기능을 지우지 않고** 위계·배치·노출을 다시 정리해서, 처음 보는 사람도 한 화면에서 "지금 무엇을 해야 하는지"와 "지금 무슨 일이 일어나고 있는지"를 바로 알 수 있게 하는 것이다.

## 1. 반드시 쓸 스킬

다음 두 스킬을 **작업 시작 전에** 읽고 따른다. Claude Code라면 Skill 도구로 호출하고, 다른 에이전트라면 파일을 직접 읽는다.

- `apple-design` — `.agents/skills/apple-design/SKILL.md`
- `design-taste-frontend` — `.agents/skills/design-taste-frontend/SKILL.md`

보조로 쓸 수 있는 스킬: `redesign-existing-projects`(기존 화면 감사 절차), `emil-design-eng`(세부 마감). 모두 `.agents/skills/`에 있다.

**충돌 시 우선순위**(`docs/design-system.md`와 같다): 기능·데이터 정확성 > 트레이딩 가독성(숫자·상태·리스크) > apple-design > taste 스킬 > 개인 취향.

이 앱은 데이터 밀도가 높은 트레이딩 터미널이고 랜딩 페이지가 아니다. 히어로, 스크롤 연출, 장식용 상시 모션, 그라디언트 장식은 적용하지 않는다.

## 2. 범위

사이드바 전체: Market, 투자(전략 · CT · 급등주), T, Backtest, Calendar, News, Lab, Settings. 우선순위는 다음과 같다.

1. **CT** — 연구 시작 화면, 진행 화면(`ct-progress.tsx`), 검증 탭(`ct-validation.tsx`), 증거 차트, 플레이북·교훈.
2. **T** — CT와 같은 구조로 정리한다. 두 화면이 같은 모양이어야 한다.
3. **전략 탭 대시보드**(`trading-dashboards.tsx`), **급등주**, **Settings**(`local-data-settings.tsx`).
4. 나머지 탭은 토큰·간격·타입 스케일 정렬 수준으로만 손본다. `docs/design-system.md`에 "Lab·News·Calendar는 7~9px 레이아웃이라 유지"라고 남은 부분은 이번에 정렬해도 좋지만, 레이아웃이 깨지지 않는 것이 우선이다.

## 3. 원칙 (구체적으로)

- **한 화면에 주 행동 하나.** 버튼 위계는 primary 하나, 나머지는 ghost나 secondary.
- **점진적 공개.** 기본 화면에는 기본값으로 바로 시작할 수 있는 최소 입력과 현재 상태 요약만 둔다. 연구 방향, 종목, 기간, 자본, 비용 한도 같은 고급 설정과 원시 JSON, 도구 로그, 장부 세부는 `ui-disclosure`나 드로어로 접는다.
- **진행 화면 요약 우선.** 맨 위 한 줄에는 상태, 단계 n/11, 경과, 비용만 둔다. 그 아래에 "지금 무엇을 하는지" 한 문장을 둔다. 스테퍼, 에이전트 카드, 피드는 그 아래 또는 접힌 영역으로 내린다. 끝난 연구는 결과(통과/미달과 사유)를 맨 위에 둔다.
- **반복 제거.** 같은 숫자(비용, 후보 수, 단계)가 여러 곳에 나오면 한 곳만 남긴다.
- **손익색은 손익과 방향에만.** 상태는 중립색, 앰버(`--warn`), danger로만 표현한다.
- **숫자는** `tabular-nums`, 해시와 코드는 mono, 한글은 `word-break: keep-all`.
- **빈 상태와 오류 상태**에는 다음 행동을 한 문장으로 안내한다.
- **모바일**(375px)에서 가로 스크롤이 없어야 한다. 표는 카드 목록으로 바뀌거나 중요한 열만 남긴다.
- **라이트와 다크** 모두 대비 4.5:1 이상(정보 텍스트).
- **모션**은 상태 변화를 설명할 때만 쓰고 `prefers-reduced-motion`을 존중한다.

## 4. 지켜야 할 제약

- **로직, API, 데이터 흐름, 폴링, 저장 형식을 바꾸지 않는다.** 마크업, 배치, CSS, 컴포넌트 분리만 바꾼다. 상태 파생이 필요하면 기존 `lib/ct-activity.ts` 같은 파생 함수를 재사용한다.
- 기능을 삭제하지 않는다. 숨기거나 옮기기만 한다. 모든 기존 정보와 버튼에 여전히 도달할 수 있어야 한다.
- 새 UI 라이브러리나 모션 라이브러리를 추가하지 않는다. 아이콘은 `lucide-react`만 쓴다.
- 토큰은 `app/globals.css`의 `:root`, 프리미티브는 `app/ui.css`(`ui-` 접두사)를 쓴다. 하드코딩한 색, 간격, 반경을 새로 만들지 않는다.
- `app/ct.css`는 `globals.css`의 `@import`가 아니라 `app/ct-*.tsx`가 직접 import한다. 이 방식을 유지한다(`@import`로 바꾸면 dev 핫리로드 때 스타일이 어긋난다).
- **동시 진행 중인 작업과 충돌을 피한다.** 코인 거래소를 Binance로 통일하고 Upbit을 제외하는 작업(지시서 C, `docs/prompts/binance-only-limit-orders.md`)이 같은 파일(`ct-workspace.tsx`, `trading-dashboards.tsx`, `local-data-settings.tsx`)을 건드린다.
  - 지시서 C가 먼저 끝났다면 그 결과 위에서 작업한다.
  - 동시에 진행한다면 **Upbit 관련 선택지·표시는 다듬지 말고 그대로 둔다**(곧 사라진다). 로직 줄은 건드리지 말고 마크업과 CSS만 바꿔서, 병합할 때 충돌을 최소화한다.

## 5. 작업 순서

1. **감사.** 앱을 실행한다(`npm run local` → http://127.0.0.1:3000. 이미 :3000이 떠 있으면 그것을 쓴다. vinext는 폴더당 dev 서버 1개). 탭마다 데스크톱과 375px, 라이트와 다크 스크린샷을 찍는다. CT·T는 시작 전, 진행 중, 완료(통과 없음) 세 상태를 모두 본다. 기존 완료 연구는 로컬 DB(`~/.qquan/state/research.sqlite`)에 있다.
2. **문제 목록.** 스킬 기준으로 화면별 문제를 표로 만든다(위계, 반복, 밀도, 대비, 모바일, 상태 표현). 심각도 순으로 정렬한다.
3. **정보 구조 제안.** CT·T 화면의 새 배치를 텍스트 와이어프레임으로 먼저 쓴다. 무엇을 맨 위에 두고, 무엇을 접고, 무엇을 합치는지. 이 제안을 문서에 남긴 뒤 구현한다.
4. **구현.** CT부터 시작해 T에 같은 구조를 적용하고, 그다음 나머지 탭을 진행한다.
5. **검증.** 같은 상태로 다시 스크린샷을 찍어 전후 비교를 만든다. 콘솔 오류 0개, 모바일 가로 스크롤 없음, 다크 모드 대비, 키보드 포커스 링을 확인한다. `npm run lint`와 `npm test`를 돌린다. 기존에 이미 실패하던 테스트와 lint가 있을 수 있으니, **변경 전 결과를 먼저 기록하고** 새로 생긴 실패만 고친다.
6. **문서.** `docs/design-system.md`에 이번 정리의 원칙, 새 배치, 감사 결과 표를 추가한다.
